## 0. 一句话

面向**大一新生**的科研启蒙助手。用户不需要注册，做一次测评拿到自己的科研画像，
按画像生成一条可以打勾的学习路线，再从**带来源的**校内教师资料与科研问答里找到下一步。

**核心闭环（已跑通）**：

```
免注册进入 → 科研测评 → 科研画像 → 学习路线 → 兴趣匹配资料 → 科研问答 → 任务打勾 → 刷新仍在
```

## 1. 产品定位（沿用 v2，未改动）

| 项 | 内容 |
|---|---|
| 名称 | 科研小助理 |
| 定位 | 面向大一新生的科研启蒙与成长助手 |
| 目标 | 让"想接触科研但不知道从哪开始"的新生，在 15 分钟内拿到一个**具体的、可执行的**第一步 |
| 核心用户 | 大一、大二学生；无科研经历；不知道该怎么找导师、读论文、写申请 |
| 非目标 | 不做论文代写；不做导师评价与人品排名；不做科研成果展示平台；不做社交 |
| 内容原则 | **只说有来源的话**。资料里没有的必须明说"无法确认"，不编造听起来合理的回答 |

### 2.2 页面逐个说明（7 个）

#### `/` 首页
- 标题「科研，从一个问题开始。」
- 两个入口：**开始科研测评** / **查看成长首页**
- 三步流程卡片
- ⚠️ 含一处**过时文案**（见 §4.1-A1）

#### `/assessment` 科研认知测评
- **题库 15 题**：9 道核心 + 6 道深入
- **进门是说明页**，不是一屏题目：含「完整版」/「演示版（更短）」两个模式 chip、
  「开始测评」、「用示例答案直接看结果」
- **两种模式的实际题量**：
  - **完整版**：核心题（9 道）**必问**；深入题**最多追 3 道**（`DEEPEN_BUDGET.full = 3`），
    且要某个维度平均分 ≥ 2 才追 → **实际 9～12 题**
  - **演示版**：只问标了 `inDemo` 的 8 题，**深入题预算为 0**
- **一次一题**：进度标签（`第 N 题 · 已答 M 题`）+ 进度条 + 「可多选」badge
- 每题都有：**「不太清楚 / 没接触过」独立选项**、可展开的**「为什么问这一题」**
- 「继续」/「上一题」；改完前面的题**后面的题会重新规划**
- 加载态：「正在准备第一个问题…」「正在想下一个问题…」
- 错误态：「先选一个，或者点「不太清楚 / 没接触过」再继续。」
- **AI 降级提示**：「当前用基础模式出题（AI 暂时不可用），题目依然会跟着你的回答变化。」
- ⚠️ 进度条口径有问题（见 §4.1-A3）

#### `/profile` 科研画像
- 阶段名（科研观察期 / 入门准备期 / 初步实践期）+ 状态总结
- 两栏对照：**「你已经具备的」** / **「接下来可以补的」**
- **兴趣方向**标签组
- **「建议优先完成的 3 个行动」**，每条带一句理由
- 底部「**这份画像的依据**」：六个能力维度的判断 + 兴趣来源 + 每周投入 + 生成时间
- 两个按钮：**根据画像生成学习路线** / **重新测评**
- 空态：「还没有你的画像…去做科研测评」

#### `/roadmap` 学习路线
- 路线标题 + 目标 + **建议周期 / 任务数 / 预计总投入**
- 进度条 + 「已完成 x / y 项」
- **按阶段分组**，每阶段有编号、标题、一句话说明
- 每个任务卡：标题、说明、**预计耗时**、**完成标准（可勾选）**
- 操作按钮：**标记为完成 / 撤销完成 / 标记为进行中 / 跳过这项 / 重新开始这项**
- **备注框 + 保存备注**（超 500 字被拒）
- 空态：「还没有学习路线」「路线还没生成」+ 生成按钮
- 失败态：提示 + **重试**
- ⚠️ 任务卡上**没有关联资料**（见 §4.1-A4）

#### `/dashboard` 成长首页
- 模块：下一步做什么 / 学习路线进度 / 最近完成 / 兴趣方向 / 推荐资料
- 无画像时是**引导空状态，不摆假数据**
- ⚠️ 「推荐资料」是**永远不变的占位文案**（见 §4.1-A2）

#### `/resources` 教师资料
- 搜索框「按姓名或研究方向搜索，例如「知识图谱」「姚俊梅」」
- 方向 chips 筛选
- **「只看官网明确提到欢迎本科生的」**开关
- 卡片：姓名、院系、职称、研究方向、邮箱、招募状态
- **查看详情 / 收起** → 展开来源（标题 + 链接 + 核验日期 + 页面更新日期）
- 来源超过 90 天会提示**重新核验**
- **画像兴趣联动**：「已从你的科研画像读到 N 个兴趣方向，命中的方向已在下方高亮」
- 空结果：「没有找到匹配的教师」

#### `/questions` 科研问答
- 输入框（含示例提示）+ 「提问」
- **12 条 FAQ 快捷入口**
- 回答卡片含：
  - 标题（取自命中的 FAQ，⚠️ 见 §4.1-A5）
  - **两个角标**：证据覆盖度（资料中有明确依据 / 只覆盖了其中一部分 / 现有资料无法确认）
    + 来源（**模型生成** / 规则回答）
  - 正文、**「下一步可以做的事」**、**依据列表（带核验日期）**、
    **「这条回答的边界」**、「怎么产生的」
- 不用注册、不消耗用户额度

#### 全局状态页
- `error.tsx`「页面暂时没能打开」+「重新尝试」
- `loading.tsx`「正在准备页面…」
- `not-found.tsx`「这个页面还没有找到」

### 2.3 服务端能力（5 个接口）

| 接口 | 作用 |
|---|---|
| `GET /api/ping` | 自检：应用是否就绪、数据库与 AI 的**配置**是否到位（不发起付费调用） |
| `GET/POST /api/session` | 匿名会话；Cookie 为 HttpOnly，服务端只存摘要 |
| `POST /api/assessment/next` | 出下一题；必带会话，否则 401 |
| `GET/POST /api/progress` | 读/写任务进度；身份只认服务端会话，请求体带他人 `userId` → 403 |
| `POST /api/questions` | 科研问答；必带会话 |

### 2.4 数据资产

| 文件 | 内容 |
|---|---|
| `data/szu-teachers.json` | **10 位**计算机与软件学院教师；字段：姓名、院系、研究中心、职称、研究方向、简介、公开邮箱、**来源**、招募状态、代表性成果（3 位有）、待确认项 |
| `data/research-faq.json` | **12 条** FAQ + **7 条**来源。FAQ 字段：问题、触发词、分类、回答、行动、来源、边界、核验日期 |

- 所有来源含 `url` / `publisher` / `evidenceSummary` / `checkedAt` / `pageUpdatedAt` / `verification`
- 加载时经 `validateDataset()` 校验并**深冻结**，资料不合格会直接抛错，不静默降级成空目录

### 2.5 AI 的两处用法（都带降级）

| 用途 | 参与什么 | 不参与什么 | 失败时 |
|---|---|---|---|
| **测评出题** | 从候选里挑下一题 | **完全不参与打分** | 降级为规则出题，界面明说「当前用基础模式出题」 |
| **问答组织** | 依据筛好的证据组织语言 | 不决定引用（引用由来源注册表还原） | 回落规则回答，角标如实显示「规则回答」 |

**共同的设计原则**：

1. **模型不参与事实判定**
2. **失败必须降级**，不报错、不空白，且**降级对用户可见**（角标会变）
3. **失败要能定位**：`SERVER_AI_DEBUG=1` 打印被拒原因与模型原文

### 2.6 状态与持久化（刷新后什么会保留）

| 数据 | 存在哪 | 刷新后 | 清空浏览器 / 换设备 |
|---|---|---|---|
| 匿名会话 | 服务端 + HttpOnly Cookie（30 天） | 保留 | 丢失 |
| 测评答案 / 画像 / 路线 | 浏览器 localStorage | 保留 | 丢失 |
| **任务进度** | **服务端数据库** | 保留 | 保留（同一会话） |

> 已知取舍：画像与路线在 localStorage，换设备就没了。这是有意为之 —— 免注册的代价。
> 如果后续要跨设备，需要引入账号体系（属 §3）。

### 3.2 v2 的 P2（时间允许再做）—— 未落地

- 更多学院 / 专业 / 实验室数据（当前只有计算机与软件学院 10 位教师）
- 路线重新规划
- 科研简历导出
- 多版本联系导师材料
- 更丰富的成长统计
- 可选 Skill 或专家包

### 3.3 能力边界（有意不做的）

- 不生成论文代写内容，不伪造科研成果
- 不对导师做评价、排名或人品判断
- **不猜名额、截止日期、当前是否招生** —— 这类必降级为「请以官方通知与老师本人回复为准」
- 不做多轮对话（当前 `maxTurns: 1`，无工具调用）
- 不做注册登录（免注册是产品前提）

### 3.4 一处**缺口**（既不是优化也不是 v2 计划，是闭环本身缺一环）

**问答给出的「行动」无法落到学习路线里。**

用户的真实经历：等约 100 秒 → 拿到 3～4 条很具体的行动 → 想去做 → **产品里没有任何入口承接**，只能自己记在别处。

- 已有实测证据：路线页上**所有可点的控件**里没有任何"新增任务"入口；回答卡片上只有来源链接可点
- 这不是加个按钮那么简单：行动的文体是**建议段落**（40～60 字），而路线任务标题约 10 字；
  且任务必须有 `estimatedMinutes` 与 `completionCriteria`，这两个数**产品不能编**
- **建议方案**（待拍板）：每条行动右侧加「加入路线」→ 内联展开三个字段 ——
  **标题**用行动原文冒号前的部分预填（模型自己的措辞，不替它改写）、
  **预计多久**与**怎么算完成**由用户填 → 加入后路线多一项，与其它任务一样可打勾。
  三条取舍理由：不跳页面（用户已经等了约 100 秒）；不改契约（三个字段用户都自己填，
  `RoadmapTask` 的类型本来就允许）；不编数据（时长与完成标准是唯一没有来源的地方）
- **待拍板**：① 做不做；② 新任务挂在哪里（新开阶段还是并入现有阶段）；③ 是否确认**不需要**改契约

## 4. 体验优化与缺陷排查（本阶段重点）

### 4.1 已确认的缺陷（有代码证据，按严重度排序）

| # | 缺陷 | 位置 | 影响 | 建议 |
|---|---|---|---|---|
| **A1** | **首页文案过时**：写着「校内资料与问答**还在接入中**」 | `src/app/page.tsx:28` | 用户以为资料与问答没上线，直接影响使用意愿 | 改成实际状态；**这是一行字的改动** |
| **A2** | **首页「推荐资料」模块永远是占位文案**：写着「还在迁入主工程，接入后这里会显示…」 | `src/features/dashboard/dashboard-view.tsx:203` | 模块**永远不产出内容**，用户看不到任何推荐 | 二选一：① 接上真实推荐（资料页已有检索能力，属"用现有能力"不是新功能）；② **先移除这个模块**，不要留一个永远空着的坑 |
| **A3** | **测评进度条口径错误**（两个症状，同一根因） | `src/features/assessment/assessment-form.tsx:307-308` | 根因：`answered` 数的是"**答案已设置**的题数"，分母是"**已走过的**题数" —— 题量又是自适应的。两个症状：<br>① **选中选项时进度条就前进**（还没点「继续」）—— 外部测试观察到<br>② **翻页后分母 +1，进度条可能回落**；第一题则接近 100%（用户会以为只有一题）—— 截图实测：第 1 题几乎满，第 2 题约 1/3 | 百分比本身是假信息（总题数事先不可知）。建议二选一：① 不显示百分比，只显示「第 N 题」；② 改成**阶段式进度**（认知 → 方法 → 技能 → 行动，题库里已有这四个维度）。另需让"选中"与"已答"分开，选中不该推进度 |
| **A4** | **路线任务没有关联资料**：`resourceIds` 恒为 `[]`，任务卡也完全不引用它 | `src/features/roadmap/plan-roadmap.ts:91` | v2 §10.3 明确要求"关联资料"。用户看到「拆解一篇论文的结构」，却拿不到那篇论文 | 把任务与 `data/` 里已有条目关联；或至少给每类任务配一条**固定且带来源**的入门材料。**不要留空数组装作有字段** |
| **A5** | **问答回答的标题与用户提问不一致**：标题取自命中的 FAQ | `composeAiAnswer` 用 `baseline.heading` | 用户问「本科生怎么联系导师」，卡片标题是「第一次联系导师怎么准备？」—— 像答非所问 | 显示**用户的原问题**，FAQ 标题降级为副标题或去掉 |
| **A6** | **有一道题该多选却是单选**：「和科研有关的活动，你参加过哪些？」`type: "single"` | `src/features/assessment/question-bank.ts:211-224` | 题干问"**哪些**"（复数），选项却是 0/1/2/3 的能力阶梯（没参加过 / 听过讲座 / 参加过竞赛 / 进过实验室）。**参加过讲座又参加过竞赛的人只能选一项** → 分数被低估 | 改成多选题，得分取最高档；或把题干改成"最高到哪一档"。**同一批题里另外两道的措辞也偏复数**（「判断一份资料可不可信，你会**看什么**」等），建议一并复核题干与题型是否匹配 |
| **A7** | **入口没有解释"为什么先做测评"** | `src/app/page.tsx` | 外部测试原话：「为什么科研小助理点进来是测评？我还以为是一个实用的工具，怎么会是测评？」—— 用户带着"工具"的预期来，第一眼看到"测评"，**预期落差直接发生在第一屏** | 在首页与测评说明页明确一句：**测评是为了先了解你，再给个性化的路线与资料**；把「开始科研测评」的措辞与"工具"的定位接上（例如「先花 2 分钟，让我知道你从哪开始」） |

### 4.2 体验问题（不是缺陷，但值得改）

| # | 问题 | 现象 | 建议 |
|---|---|---|---|
| **B1** | **AI 等待期间没有反馈** | 问答实测 24～132 秒，期间只显示"查询中" | ① 显示**已等待秒数**；② 超过 20 秒提示「还在生成，可以先去别的页面看看」；③ 给出**预期区间**（15～60 秒）而不是让用户干等 |
| **B2** | **测评的 AI 等待同样无反馈** | 完整版有 2 次 AI 介入，每次约 20～30 秒 | 介入时已有"衔接语"，可再补一句「正在根据你的回答调整后面的题…」 |
| **B3** | **问答页 12 条 FAQ 常驻占一屏** | 回答出现后 FAQ 仍铺满 3 行 | 回答出现后**折叠** FAQ，把注意力让给回答 |
| **B4** | **行动的长段落** | 3～4 条行动各 40～60 字，扫读成本高 | 每条行动**加粗首句**（冒号前那部分天然就是短标题）；这个改动也能直接服务 §3.4 |
| **B5** | **「依据」只有 1 条且是国外高校** | 问"深大老师怎么联系"，依据是 Stanford 的页面 | 回答正文与边界已诚实说明（「按斯坦福的一般性建议…不是深圳大学的规定」），**不算错**；但数据扩充时补一个国内高校或深大自己的来源会更稳 |
| **B6** | **「为什么问这一题」这个栏位名不明所以** | 外部测试原话：「很好的小栏：不明所以，用户看不懂」 | 这个折叠栏本身是好设计（解释出题意图），但**五个字没说清它是什么**。改成「这一题在了解什么？」之类，或在旁边加一行小字说明 | 
| **B7** | **选项覆盖不到用户的真实情况** | 外部测试举例：某题问"找论文你会怎么做"，用户想答"**用 AI**"，但三个选项是按"普通搜索 → 学术工具"的能力阶梯写的，**AI 辅助检索落在阶梯之外**；选了会被判成低档 | 报告者自己建议"加一个自由输入框"，并补了一句"**如果技术上复杂不建议使用**"。**这属于新增功能，本阶段不做。** 可考虑的轻量做法：给选项不足的题补一个「**我的做法不在上面**」，至少让用户不被强制选一个假答案 |
| **B8** | **视觉单薄：缺图、对比度不足、不够吸引人** | 外部测试把它列为 **T0 最高优先级**：「需要增加一点图片和外观，ui 设计对比度明显一点，图片实在太少了。缺少吸引人的地方」 | 不新增内容的前提下可做的：提高标题与正文的**对比度与层次**、给空状态与卡片补**视觉锚点**。⚠️「放新闻/动态 UI」属新增内容与新功能，**本阶段不做** |

### 4.3 待排查的疑点（尚未验证，供下一轮排查）

1. **自适应测评的疲劳感**：题量已经查清 —— **完整版 9～12 题**（核心 9 必问 + 深入最多 3），
   **演示版 8 题**。要验的是**感受**：全部选最高档时会问满 12 题，
   对大一新生会不会太长？建议实测「全选最高档」与「全选最低档」两条极端的题数与耗时。
2. **「上一题」改动后重新规划的幅度**：改动会不会让已经答过的题被重复问？
3. **演示模式的边界**：`isDemo` 角标出现在 profile / roadmap / dashboard / resources 四页，
   但 **`/questions` 与 `/assessment` 没有**。用户在演示模式下提问，回答里没有任何"这是演示"的提示 —— 是否需要补？
4. **localStorage 与 session 不一致**：画像/路线在本地，进度在服务端。若 session 过期（30 天）而本地数据还在，
   页面会不会显示"有路线但进度读不出来"？
5. **问答的规则兜底覆盖度**：规则引擎有 9 条处理分支，但是否存在**既没匹配 FAQ、又没匹配方向**的问句直接落到兜底？
   兜底回答对用户是否有用？
6. **⭐ 选项是否覆盖了"AI 时代的学习方式"**（由外部反馈 B7 引出的更大的问题）：
   现有选项是按"普通搜索 → 学术工具"这种**传统科研路径**的能力阶梯写的。
   但这一代新生的真实做法可能是"**用 AI 找文献 / 用 AI 读论文 / 用 AI 解释术语**" ——
   这些人会落到阶梯之外，只能选一个假答案，进而被**系统性地打低分**，
   而低分又会把 ta 导向一条过于基础的路线。
   **建议逐题复核选项**：每道题都问一句"一个习惯用 AI 的大一学生会怎么答？他能找到自己的选项吗？"

## 5. 已知边界与技术约束

| 项 | 说明 |
|---|---|
| 免注册的代价 | 画像与路线在浏览器本地，换设备就没了 |
| AI 延迟 | 单次 24～132 秒（CLI 子进程固定开销 + 模型生成）；**波动很大**，曾出现 180 秒超时 |
| AI 可用性的兜底 | `SERVER_AI_QA_MODE=off` 可随时停掉问答的模型调用，回答内容不变、降到 1 秒级 |
| 额度 | AI 走个人额度，站点公开可访问 → 因此**证据不足的提问根本不调模型** |
| 数据规模 | 10 位教师 / 12 条 FAQ / 7 条来源，全部限定在计算机与软件学院 |
| 线上可达性 | `*.vercel.app` 域名在中国大陆被针对（DNS 污染 + SNI 重置），**自定义域名可解决**（本轮决定不买） |
| 线上操作权限 | Vercel 是 Kevin 个人账号，**只有他能改环境变量与重新部署** |
| 数据库 | CloudBase PostgreSQL，只能走 HTTP/PostgREST（`pg` 协议不可用） |
