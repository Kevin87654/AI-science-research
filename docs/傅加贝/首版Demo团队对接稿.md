# 毕业设计管理需求与技术计划

2026 年 11 月 10 日 · 团队对接稿 · 基于 V0.1 讨论

## 1. 项目目标

面向本科毕业设计学生、指导教师和教务管理人员，建立一套可追溯的毕设工作记录。学生能查到各阶段的截止时间和材料要求，按周记录真实进展；教师能集中查看所指导学生的任务、周记录和成果，并及时反馈；管理员能维护官方阶段和师生关系。

Demo 的目标是用模拟数据走通一次完整业务流程：管理员初始化数据，学生查看官方阶段、制定任务并提交周记录，教师审阅反馈，学生查看反馈并调整下一周计划。开发和验收均可使用演示环境。

## 2. 角色与功能需求

| 角色 | 主要功能 | 权限边界 |
| --- | --- | --- |
| 学生 | 查看课题和官方阶段；创建任务；记录每周工作、问题和下周计划；关联成果；查看反馈 | 维护自己的任务、周记录和成果 |
| 指导教师 | 查看指导学生列表、当前阶段、最近提交时间和待审阅记录；查看学生详情；填写文字反馈 | 仅访问所指导学生的数据，保留学生原始记录 |
| 管理员 | 导入学生、教师、课题和师生关系；维护官方阶段、材料要求与截止时间 | 负责基础数据和官方安排 |

**双时间轴。** 官方时间轴记录学校发布的阶段、起止时间、任务和材料要求，由管理员维护。个人时间轴按周记录计划、实际工作、成果、问题和下周安排。两条时间轴分别存储，通过任务和成果建立关联。调整官方阶段时，学生历史记录仍可查询；完成个人任务后，官方阶段的审核状态须按学校流程处理。

**任务、周记录与成果。** 任务记录计划起止时间、实际完成时间、状态和关联阶段，状态包括未开始、进行中、已完成、已阻塞和已取消。一个任务可以跨多周，一条周记录可以关联多个任务，同一份成果可被不同任务和周记录引用。演示中可先用样例成果展示关联，实际上传随成果管理完善。

**教师审阅与提醒。** 教师从工作台进入学生详情，对周记录或成果留下文字反馈和审阅状态。后续按明确规则提示任务逾期、临近截止和待审阅事项，分别呈现各项状态。学生可以在周记录中说明未完成任务的原因。

## 3. 页面与演示流程

| 入口 | 内容与操作 |
| --- | --- |
| 登录页 | 输入预置教育邮箱，使用模拟验证码进入对应角色工作台 |
| 学生主页 | 展示课题、当前官方阶段、近期截止事项、任务和最近周记录 |
| 个人时间轴与周记录编辑页 | 按周浏览，填写进展和问题，关联任务及成果，查看教师反馈 |
| 教师工作台与学生详情 | 按指导关系列出学生，查看双时间轴、任务与周记录，提交反馈 |
| 管理后台 | 维护或导入演示用的人员、课题、师生关系和官方阶段 |

演示以「开题准备」为例。管理员导入示例阶段和师生关系；学生查看开题要求，创建文献调研任务，提交关联该任务的周记录；教师查看并反馈；学生在个人时间轴中看到反馈，并据此更新任务或填写下一周计划。

## 4. 技术方案

采用模块化单体方案。以下技术选型沿用 V0.1 建议，待团队结合开发和部署条件确认。

| 层次 | 方案 |
| --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Tailwind CSS。按学生、教师、管理端划分路由，复用阶段和周记录组件 |
| 后端 | FastAPI。按认证、人员与项目、官方阶段、任务与周记录、成果、反馈、导入划分模块，由 API 提供读写能力 |
| 数据 | Demo 使用 SQLite，正式环境可评估 PostgreSQL。以 JSON 或 Excel 初始化演示数据 |
| 身份与权限 | 服务端会话；后端同时校验角色、项目归属与师生关系。教育邮箱验证码验证邮箱归属，角色由用户档案确定 |
| 外部对接 | 邮件发送通过统一接口封装，演示环境使用模拟实现；正式环境按校方授权选用 SMTP 或邮件 API。学校数据可先评估 Excel 导入，再视授权对接学校接口 |

**核心数据模型。** 用户通过项目成员关系关联毕设课题和指导教师。官方阶段单独维护，记录阶段要求，并预留变更记录。个人任务、周记录和成果归属具体项目，采用关联表表示多对多关系。教师反馈记录作者、时间、审阅状态和被反馈的周记录或成果。

**演示与正式环境。** 演示仅使用模拟人员、课题和阶段。正式环境需确认学校数据授权、支持的邮箱范围与邮件发送方式，落实验证码有效期和发送限制、访问日志、数据保留与备份。模拟验证码限定在开发和演示环境。

## 5. 开发顺序与验收

| 阶段 | 交付范围 | 验收方式 |
| --- | --- | --- |
| 1. 学生端基础 | 模拟邮箱登录、基础权限、演示数据、官方时间轴、个人时间轴、任务和周记录 | 学生能查看阶段、创建任务并提交关联周记录；重新进入后仍能查看 |
| 2. 教师协作 | 教师工作台、学生详情、周记录审阅、文字反馈和基础提醒 | 教师能为所指导学生提交反馈，学生可见；验证其他学生的数据访问被拒绝 |
| 3. 演示完善 | 成果上传与关联、筛选、导出、统计和页面体验优化 | 一份成果可关联多条记录，按约定完成筛选与导出；演示流程可从初始化重复执行 |
| 4. 正式对接 | 学校数据和邮件接入、正式部署、安全与隐私检查 | 在获授权的环境中验证数据导入或同步、登录、权限和备份恢复 |

建议在前两阶段先用初始化脚本准备数据。管理后台、实际文件上传及统计导出何时进入演示，按团队确认的范围安排。联调时用至少两组模拟师生关系验证数据隔离，并验证修改官方阶段后历史周记录仍可查看。

## 6. 团队需要确认的事项

| 议题 | 对接时要定下来的内容 |
| --- | --- |
| 交付与分工 | 首次演示包含哪些页面和操作；明确前端、后端与数据、联调验收各环节负责人和时间 |
| 技术与运行 | 确认技术栈、演示部署位置和启动方式；确定演示数据如何初始化和重置 |
| 业务规则 | 确认周记录提交后能否修改、审阅后如何修订、联合指导教师的访问范围 |
| 校方沟通 | 核实实际阶段安排、可提供的数据字段与更新方式、邮件授权和部署条件 |
