# 协作卡片增量接入

基于 `90e1d59` 增量接入正式提交与解惑流程，沿用仓库现有聊天、进度 AI 和页面样式。代码通过独立开发分支提交，供团队审查后合并。

## 界面接入

- 沿用「联系导师 / 联系学生」，在原聊天面板内加入「提交与解惑」卡片区。原普通聊天、进度 AI 和 14 个学校阶段保留。
- 学生可以正式提交已有进度及补充说明；AI 汇总结果新增「转为正式提交（可编辑）」，进入同一聊天中的确认表单。原汇总消息不自动成为正式提交，仍需学生确认。
- 正式提交保存独立的节点快照。导师可通过或要求修改，返修在同一记录下增加轮次，保留原提交和意见。正式提交按需进行，不限制每周只能一份。
- 解惑只需填写问题，双方在问题内回复。学生标记解决或重新打开；需要面谈时任一方再提出时间地点，由另一方确认。
- 会面确认检查学生及导师的时间冲突；过期提议不能确认。取消、完成和问题解决各自记录。学生解决问题时取消尚未确认的提议，已确认会面仍需单独取消。
- 学生个人进度中合并展示已确认、已完成的会面；会面入口返回原联系页面。普通自建节点仍可删除，会面不能通过普通节点删除。

## 服务端与数据

新增 `GET/POST /api/graduation/workflow`，仍走原 catch-all API，不新增独立服务。前端通过原 API 客户端获取会话并请求数据，每两秒同步，操作前后防止旧轮询结果覆盖新状态。

业务状态由 `workflow-model.ts` 维护；`MemoryWorkflowRepository` 提供读取、复制、状态更新及跨会话冲突检查，供以后替换成数据库事务。当前与仓库原聊天一样使用服务端进程内存，支持同一服务进程下的跨浏览器协作，重启即清空，多实例之间不共享，尚未接入数据库。

现有身份仍是演示实现：接口要求匿名 Cookie、有效演示账号及会话标识，操作角色由客户端声明。状态层检查角色和记录所属会话，无法替代真实账号认证。接数据库时需要一并将发送人从服务端账号会话解析，不能把目前实现用于真实学校数据。

## 验证

171 项测试通过，覆盖原仓库规则及新增的快照、反馈轮次、会话隔离、双向确认、跨会话时段冲突等。浏览器使用两个隔离的数据环境验证 AI 草稿转提交、导师返修、再次提交、历史回看、问题回复、会面确认、个人进度、普通聊天和移动布局；不需要付费 AI 配置即可验证规则回退路径。

本地预览仍为 3001 端口，耦合版另行保留。
