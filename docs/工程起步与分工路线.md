## 代码放在哪里

```text
src/
  app/                 页面与 HTTP 入口；薄层负责输入校验和响应
  components/          通用展示组件，不读取密钥或直接访问数据库
  contracts/           前后端共享的可序列化类型
  features/            按业务分组的交互组件、规则与纯函数
  server/
    services/          业务流程；通过接口使用数据库和 AI
    repositories/      数据访问接口；内存实现与 CloudBase HTTP 实现
    ai/                AI 接口与 CodeBuddy 实现
    auth/              匿名身份及服务端归属校验
data/                  可提交的公开来源资料与明确标识的演示资料
scripts/migrations/    经评审的迁移源文件
cloudbase/migrations/  实际执行产生的迁移记录，执行后再纳入仓库
```

没有具体实现的目录只用于说明责任，不预建虚假的业务功能。服务端入口使用 `server-only`，浏览器代码不得导入服务端模块。共享展示组件与契约另有 ESLint 限制。业务 Service 保持可注入依赖，评分等纯函数放在 features 中，方便脱离网络验证。

普通 JSON 接口返回 `ApiResponse<T>`。成功为 `{ ok: true, data }`，失败为 `{ ok: false, error: { code, message, requestId } }`，并使用对应 HTTP 状态码。错误正文面向用户，不返回密钥、数据库响应原文或调用堆栈；服务端日志也需去除敏感内容。AI 流式事件协议在接入时单独确定，不把 HTTP JSON 类型强套在流上。

## 初版默认处理建议

- 移动端：同一套网页适配手机，优先保证 360–390px 宽度无横向溢出、表单和按钮可操作、文字可读；不开发独立 App。
- 测评：评分使用可解释的确定性规则；AI 可辅助解释和建议。具体题目、维度权重、题数待范围讨论后共同确认。
- 路线：先稳定输出有预计耗时和完成标准的任务；重新规划与历史多版本延后。
- 资料：先覆盖团队选定的小范围，每条真实资料都记录公开来源和核验日期。优先保证准确，数量等团队讨论。
- 演示：独立且明确标识的演示数据，不混入真实匿名用户记录。演示模式从第一条流程开始接入，不拖到最后。
- 测试隔离：本地纯逻辑与模拟数据先独立验证；真实 CloudBase 接入只使用专门标识的测试记录。独立 schema 能否经当前 HTTP 网关使用需先验证，不默认已经可用。

## 下一阶段必须先对齐的契约

由三人共同确认一份最小样例 JSON：测评提交、画像结果、路线与任务、任务进度、资料与引用。每个字段说明含义与是否可空。契约先只覆盖第一条可验收流程，暂不设计全部 PRD 的大而全数据库。

匿名身份由服务端确认，业务接口不可直接信任浏览器提交的 userId。每个 Repository 查询都要带经过验证的用户归属；持有管理员级 Key 不能替代用户鉴权。完成真实接口后，必须验证跨用户读取和修改均被拒绝。

首次 migration 由 Kevin 统筹，走既有交接文档的评审与人工投递流程；其他人提出字段需求，不各自直接建表。RPC、真实 AI 工具调用、跨云延迟和线上可达性各有独立探针与结果，不能用“首页能打开”代替全链路通过。

## 配置与协作

Node.js 固定 24.x，pnpm 固定 11.19.0。安装使用 `pnpm install --frozen-lockfile`，修改依赖时连同锁文件一起评审。首次独立类型检查使用 `pnpm typecheck`，它会生成 Next.js 路由类型；提交前统一运行 `pnpm check`。

ESLint 暂用 9.39.5：当前 Next.js 配套的 eslint-plugin-react 声明支持至 ESLint 9，贸然升至 10 会超出其兼容范围。该版本已收到上游停止支持提示，后续配套插件支持 10 后再一起升级；当前不通过忽略 peer 冲突强装。

本工程统一使用 `.env.example` 中的 `SERVER_` 前缀。交接说明中的 `CLOUDBASE_PG_REST_BASE_URL` / `CLOUDBASE_PG_API_KEY` 对应工程中的 `SERVER_CLOUDBASE_PG_REST_BASE_URL` / `SERVER_CLOUDBASE_PG_API_KEY`。AI 接入时从服务端配置映射到 SDK 子进程需要的变量；目前模板不代表已经接通。真实 Key 不填入 example、源码、日志或浏览器请求。

代码在个人分支开发，按 CONTRIBUTING 发 PR，由至少一名队友确认后合并。公共底座合并后，其余两人同步 main，再开始业务开发。不要三个人各自初始化项目，也不要以重建环境的方式解决测试数据问题。
