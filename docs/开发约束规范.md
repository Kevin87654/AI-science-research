## 2. 作品能力要求（从评分倒推）

**这一节回答"要建出什么"，第 3 节之后回答"怎么建"。** 评分权重直接决定我们的精力分配：

| 评分维度 | 分值 | 对我们的硬性含义 |
|---|---|---|
| 技术创新性 | **30%** | AI 应用要有**深度**，不能是"输入问题→吐答案"的一问一答 |
| 工程完整性 | **25%** | 代码质量、架构设计、功能完备。**要有分层、有错误处理、能复现** |
| AI 工具使用 | **25%** | LearnBuddy 使用深度 → 见 §7 |
| 用户体验 | 20% | 界面设计、交互流畅度、功能可用性 |

### 2.1 "智能体特质"的三条最低要求（对应 30%）

赛事原文要求作品"具有**智能体**特质"，不是"有一个 AI 功能"。三条至少要满足两条：

1. **工具调用（function calling）**：由模型自己决定调用哪个工具（解析文献 / 检索实体 / 查图谱 / 生成综述），而不是把流程写死在前端。
2. **多步过程可见**：把中间结果暴露给用户看（抽出了哪些实体、依据哪句原文）。这同时拿"技术创新性"和"用户体验"两项分。
3. **有沉淀**：用户确认过的结论进入知识库，后续可被引用。让作品"越用越聪明"。

### 2.2 工程完整性的最低要求（对应 25%）

- 严格按 §4.1 分层，Route Handler 里不放业务逻辑。
- 所有外部调用有超时、有错误处理、有用户可读的失败提示。
- 关键 service 函数至少有一层可验证的输入输出约定（类型 + 校验）。不强制写测试，但**必须能在本地一条命令跑通全链路**。

### 2.3 用户体验的最低要求（对应 20%）

- 任何超过 2 秒的操作**必须有加载状态**。
- 批量处理必须有**进度反馈**（第几篇 / 共几篇）。
- 失败状态必须告诉用户"哪一步失败了、能不能重试"，不允许白屏或静默失败。

## 3. 平台约束（Vercel 单平台）

### 3.1 免费版（Hobby）的实际限制

| 维度 | 限制 | 来源 |
|---|---|---|
| 单次函数最长执行 | **300 秒**（默认＝上限） | `[官方]` |
| 请求 / 响应 body | **4.5 MB**，超出返回 413 `FUNCTION_PAYLOAD_TOO_LARGE` | `[官方]` |
| 函数 bundle 大小（解压后） | 250 MB（Node.js） | `[官方]` |
| 内存 / CPU | 2 GB / 1 vCPU，**不可配置** | `[官方]` |
| 函数区域 | **只能选 1 个区域**，默认 `iad1`（美东） | `[官方]` |
| 文件描述符 | **1,024 个，所有并发执行共享** | `[官方]` |
| 持久化文件系统 | 无（`/tmp` 临时，实例销毁即丢） | `[官方]` |
| Docker / 容器 | 不支持，只能源码构建 | `[官方]` |
| 月度额度 | 100 万次调用 / 4 CPU-小时 active CPU / 100 GB 传输 / 360 GB-小时内存 / **100 次部署每天** | `[官方]` |
| **运行时日志保留** | **仅 1 小时** | `[官方]` |
| 商业用途 | **仅限非商业个人使用** | `[官方]` `[待核实]` |

三条必须理解透的细节：

1. **active CPU 只算代码真正执行的时间，I/O 等待不算。** 也就是说"等大模型返回"这段时间**不吃** CPU 额度。这是好消息——AI 应用的主要耗时在 I/O 而非计算。
2. **额度超了不会自动扣费，而是暂停项目**，直到下个周期或升级。`[待核实]` 对我们的意思是：答辩当天如果额度耗尽，链接会直接报错，没有缓冲。所以演示前要盯住用量。
3. **日志只留 1 小时。** 线上出问题必须立刻去看，过一小时就没了。这是免费版最容易坑人的地方。

### 3.2 由限制推导出的硬性禁令

1. **禁止把用户上传的文件写进本地磁盘。** 没有持久化文件系统。上传即落对象存储（§5.3）。
2. **禁止使用 SQLite 或任何嵌入式数据库。** 冷启动即丢数据。用外部 Postgres。
3. **禁止让超过 4 MB 的文件经过函数请求体。** 硬上限 4.5 MB，且**Server Actions 和 Route Handlers 都适用** `[官方]`。超过就 413，没有配置开关能改（限制在基础设施层）。必须走客户端直传（§5.3）。
4. **禁止使用 `export const runtime = 'edge'`。** 理由（Vercel 官方文档明确）：**流式输出和 SSE 在默认的 Node.js runtime 上原生支持，不需要 Edge runtime**；Edge 不但没有流式优势，还把首字节限制在 25 秒以内，并且拿不到完整 Node.js API 和 npm 生态。→ 保持默认 Node.js runtime。
5. **禁止不设超时的外部调用。** 大模型、数据库、对象存储，每一个都必须有超时。
6. **禁止把密钥写进代码或前端。** 见 §5.5。
7. **禁止在单次请求里做"一次性处理全部文献"的长任务。** 见 §6.1。

### 3.3 必须显式配置的三件事

**（1）函数区域设为 `hkg1`（中国香港）**

Hobby 版只能选一个区域，默认是 `iad1`（美东）。这意味着**默认配置下，每次 API 调用都要跨太平洋一个来回**，而我们的评委在深圳。

- 函数区域：设为 `hkg1`，退一步 `sin1`（新加坡）。
- **数据库区域必须与之匹配**（选亚太节点）。
- 函数在美东、数据库在新加坡这种组合，会让每次查询都跨洲，是性能杀手。

配置位置：Vercel 控制台 → 项目 → Settings → Functions → Regions。

**（2）函数最大时长**

在需要长时处理的 Route Handler 里显式声明：

```ts
export const maxDuration = 300; // 秒，Hobby 上限即 300
```

**（3）运行时文件打包声明**

我们的 `content/` 目录（提示词、schema、领域知识）在运行时需要被函数读取，**Vercel 不会自动打包这些文件**。必须在 `next.config.ts` 里声明：

```ts
outputFileTracingIncludes: {
  '/api/**': ['./content/**/*'],
}
```

> 每次往 `content/` 新增一级目录，**必须同步更新这个配置**。这个坑只在线上才暴露——本地 `next dev` 一切正常。

## 4. 技术栈（已锁定，不得擅自替换）

### 4.1 主栈

| 用途 | 选型 | 锁定理由 |
|---|---|---|
| 全栈框架 | **Next.js（App Router）+ TypeScript** | Vercel 的母公司产品，零配置、最佳路径 |
| Node 版本 | 锁定 `22.x`（在 `package.json` 的 `engines` 声明） | 避免本地与线上不一致 |
| 界面 | **Tailwind CSS + shadcn/ui** | 10 天做出不难看的界面 |
| 服务端逻辑 | **Route Handlers**（`app/api/**/route.ts`）+ Server Actions | 这就是我们的后端，无需独立服务 |
| 模型调用 | **Vercel AI SDK**（`ai` + `@ai-sdk/openai`） | 自带流式、function calling、前端 `useChat`；指向 OpenAI 兼容端点，换模型只改 base_url |
| 数据库 | **Postgres**：Neon 或 Supabase | 见 §4.3 的连接池要求 |
| 向量检索 | **pgvector** | 与 Postgres 同库，少一个外部依赖 |
| 对象存储 | **Vercel Blob** | 官方客户端直传模式最省事，免 CORS 配置 |
| 图谱可视化 | **Cytoscape.js** 或 **react-force-graph** | 现成力导向图组件，支持拖拽/点选/缩放 |
| PDF 解析 | Node.js 侧解析库（如 `unpdf` / `pdf-parse`） | 必须在 Node runtime 跑 |

### 4.2 一条低成本的设计习惯（与 Skill 无关，本身就值得）

**提示词、schema、领域知识统一放仓库根的 `content/`，不硬编码在 `.ts` 文件里。**

```
content/
├── prompts/     所有提示词（.md）
├── schemas/     实体类型 / 关系类型 / 分类体系（.json 或 .yaml）
└── domain/      领域知识、术语表、分类学
```

理由（不需要"为了 Skill"就成立）：
- 改提示词不用改代码、不用重新理解业务逻辑，迭代快得多。
- 能对比不同版本提示词的效果，这是拿"技术创新性"分的基础。
- schema 只定义一份，前后端共用，不会出现"两边定义不一致"的经典 bug。

**附带好处**：如果将来决定做 Skill（附录 A），这套结构可以直接复用，不需要返工。

### 4.3 数据库必须走连接池

Serverless 函数每次调用都可能新建数据库连接，而 Vercel 的**文件描述符上限是 1,024 个且所有并发执行共享** `[官方]`。Vercel 官方文档明确建议：**对数据库连接使用连接池**。

- Neon：使用 `-pooler` 后缀的连接串
- Supabase：使用 Supavisor 连接池端点（端口 6543），**不要用直连 5432**

**这是 serverless + Postgres 最经典的坑**：本地测试一切正常，一上线几百个并发就把连接数打满。

### 4.4 禁止引入的东西

- ❌ 需要 Docker 的任何组件
- ❌ 重量级向量数据库（Milvus / Weaviate / Qdrant 自建）→ 用 pgvector
- ❌ 图数据库（Neo4j 等）→ 用 Postgres 的 `nodes` / `edges` 两张表
- ❌ 任何"必须先本地训练模型"的方案
- ❌ 需要独立常驻服务的后端框架（配合 Vercel 部署只会增加复杂度）

> **不再禁止**：Vercel 官方存储（Blob / 数据集成）。v1.0 禁止它们是为了双平台兼容，现已无此必要。

## 5. 架构约束

### 5.1 分层与职责

```
浏览器（React 组件）
    ↓ fetch / useChat
Route Handler（app/api/**）        ← 唯一服务端入口，Node.js runtime
    ↓
Service 层（src/lib/services）     ← 业务逻辑，纯 TS，可在本地直接调用测试
    ↓
适配器层（src/lib/adapters）       ← 数据库 / 对象存储 / 模型，接口固定，实现可换
    ↓
外部服务（Postgres / Vercel Blob / 大模型 API）
```

**硬性要求**：Route Handler 里不允许出现业务逻辑，只做「校验入参 → 调 service → 返回响应」。

### 5.2 长任务的两种模式

| 模式 | 适用 | 做法 |
|---|---|---|
| **批处理** | 抽取、入库、embedding | 前端拆批 + 逐批调用 + 进度条 |
| **流式** | 问答、综述生成 | Route Handler 返回流，AI SDK 的 `toUIMessageStreamResponse()` + 前端 `useChat` |

流式在 Node.js runtime 上原生支持，**不需要 Edge runtime**（见 §3.2 第 4 条）。

### 5.3 大文件必须客户端直传

超过约 **4 MB** 的文件，**不允许经过 Route Handler 的请求体**。

标准做法（Vercel 官方推荐）：
```
1. 前端向服务端请求一个短时效的 token
2. 前端用 @vercel/blob/client 的 upload() 直传 Blob（文件不经过函数）
3. 前端把返回的 URL 交给 /api/ingest，由服务端分批处理
```

好处：完全绕开 4.5 MB 限制，且不产生数据传输费用。**不要试图把上传大小限制"设大一点"来绕过——限制在基础设施层，改不了。**

### 5.4 缓存是免费额度里最值钱的东西

Vercel 上，**每一层放在函数前面的缓存，都是一次不会被计费的调用**。适合缓存的：图谱静态数据、文献列表、已生成的综述。用 `Cache-Control` / `revalidate` 让 CDN 承担重复访问。

### 5.5 密钥与环境变量

- 所有密钥通过环境变量注入。本地用 `.env.local`（**必须在 `.gitignore` 中**），线上在 Vercel 控制台配置。
- **服务端专用变量用 `SERVER_` 前缀**（如 `SERVER_LLM_API_KEY`）；只有确定可公开的才用 `NEXT_PUBLIC_`。
- 前端代码里出现任何密钥 ＝ 严重违规。提交前必须全仓搜索。
- Vercel 环境变量区分 Production / Preview / Development，配置时注意别只配了一个环境。

### 5.6 冷启动要有心理预期

Hobby 版没有预热实例，首次调用有冷启动。实测参考量级：冷启动约 1–3 秒，热态约 0.5–1 秒 `[待核实]`。

含义：**演示前先"预热"一次**（提前访问一次，让实例起来），避免答辩第一条请求就卡 3 秒。

## 6. 性能与超时预算

### 6.1 分档预算

| 场景 | 预算 | 理由 |
|---|---|---|
| 面向用户的同步交互（问答、检索） | **≤ 30 秒** | 超过 30 秒用户会以为卡死 |
| 批处理单批（解析 + 抽取 N 篇） | **≤ 120 秒** | 留足重试与抖动余量 |
| 任何单个请求的硬上限 | **≤ 180 秒** | Vercel 上限 300 秒，留 40% 余量 |

保留"拆批"要求的真正理由（不再只是为了超时）：
- **用户体验**：不能让人对着转圈等 5 分钟
- **可重试**：单批失败只重试这一批，不用从头来
- **可观测**：进度条是"用户体验 20%"的得分点

### 6.2 单请求时间分配

| 环节 | 预算 |
|---|---|
| 大模型单次调用 | ≤ 30 秒（必须设超时） |
| 单篇 PDF 解析 | ≤ 10 秒 |
| 数据库写入 | ≤ 5 秒 |
| 其余 | 预留给重试与网络抖动 |

### 6.3 必须做的三件事

1. **所有外部调用设超时**，一个都不能裸调。
2. **失败要有降级**：返回可读错误 + 允许重试，不能让页面白屏。
3. **禁止在渲染路径上做重活**：首屏不做解析、不做批处理，一律后台触发 + 轮询。

## 7. 过程记录约束（占 25%，且不可补）

评分里"AI 工具使用（LearnBuddy 使用深度）"占 **25%**，提交材料要求"开发过程中与 AI buddy 的历史对话记录"。

- **从今天开始，所有实质性设计讨论、代码生成、调试过程都通过 LearnBuddy 进行**，不要为了"代码更干净"而绕开它。
- 关键决策（选题收窄、架构选择、为什么放弃某个方案）**要留下讨论过程**，不要只留结论。
- 赛后要能拿出**过程**，不是拿出现成的答案。赛事明令禁止"用 AI 生成完整方案后直接提交"。
- **不允许事后编造对话记录**（既违规也容易被识别）。
- 每完成一个阶段，把关键结论沉淀进 `docs/`，保证过程可追溯。

### 9.2 约束合规检查

- [ ] 没有任何 `runtime = 'edge'`

## 12. 如何修改本文档

1. 确认改动是**必要的**（而不是"这样写起来更爽"）。
2. 判断影响范围：是否会波及已写的代码？先评估工作量。
3. 修改正文，**同时更新顶部版本号和改动记录**。
4. 改动若源自一次踩坑或新发现的事实，把原始依据（链接、报错、实测数据）记进改动记录。
5. 重大改动（技术栈、部署平台、架构分层）**必须全队确认**。

### 改动记录

| 版本 | 日期 | 改动内容 | 依据 |
|---|---|---|---|
| v1.0 | 2026-09-16 | 首次建立 | 赛事手册、赛事群答疑、Vercel 与 EdgeOne 官方文档 |
| **v2.0** | 2026-09-16 | **见下方 v1.0 → v2.0 详细说明** | Vercel 官方函数限制文档、上传指南、Workspace 定价页 |

#### v1.0 → v2.0 修订说明

**决策变更**

1. 部署平台从"Vercel + EdgeOne 双目标"改为 **仅 Vercel**。所有为双平台兼容而设的约束重新评估。
2. Skill 沉淀从**硬要求降级为待选项**（移入附录 A）。

**推翻的约束**

3. **请求超时 90 秒 → 分档预算**（同步 30s / 批处理 120s / 硬上限 180s）。原 90 秒是按 EdgeOne 的 120 秒上限定的，Vercel 上限是 300 秒。
4. **"禁止依赖平台专有 API"删除。** 该禁令的唯一理由是双平台兼容，现已无必要。改为**推荐 Vercel Blob**。
5. **"禁止 WebSocket 长连接"删除。** 这是 v1.0 的**事实错误**——Vercel Functions 支持 WebSocket 长连接（需 Fluid Compute，默认开启）。只是我们不需要，而非平台不支持。
6. **EdgeOne 相关的所有约束删除**：`edgeone.json`、`cloudFunctions.nodejs.includeFiles`、Next.js rewrites 禁令、EdgeOne 构建次数等。

**修正的事实错误**

7. **streaming 不需要 Edge runtime**——这是 v1.0 说对了结论但说错了理由的地方。正确理由是 Vercel 官方文档明确写明的：**流式和 SSE 在默认 Node.js runtime 上原生支持，Edge 反而没有优势且首字节限 25 秒**。
8. **打包命令硬编码本机绝对路径**（`D:/LearnBuddy/...`）改为可移植写法，见附录 A。

**新增的遗漏项**

9. **函数区域配置**（§3.3）——Hobby 默认 `iad1`（美东），每次调用跨太平洋，而评委在深圳。**这是原文档最大的遗漏**。
10. **数据库连接池**（§4.3）——Vercel 文件描述符 1,024 上限 + serverless 连接爆炸，官方明确建议连接池。
11. **`LICENSE` 文件要求**（§9.3）——赛事要求"开源（MIT/Apache 2.0/GPL）"，不只是公开仓库。
12. **作品能力要求章节**（§2）——原文档只约束了"怎么建"，没约束"建出什么"。新增按评分倒推的最低要求。
13. **冷启动**（§5.6）、**缓存策略**（§5.4）、**日志仅留 1 小时**（§3.1）、**额度耗尽暂停项目**（§3.1）。
14. **已接受的风险**独立成节（§10），把 vercel.app 大陆访问问题明确记录在案。
