## 三、技术路线（速查）

> 完整的"已确定架构"见《AI实施任务书》§1，本节只是速查。

```text
浏览器
  → Next.js App Router + TypeScript
  → Vercel Functions（区域 hkg1）
  → Repository 数据适配层
  → HTTPS / PostgREST
  → CloudBase PostgreSQL 17
```

| 项 | 值 |
|---|---|
| 框架 | Next.js App Router + TypeScript，Node 22，**pnpm** |
| UI / 表单 | Tailwind CSS + shadcn/ui，React Hook Form + Zod |
| 数据库 | CloudBase PostgreSQL 17（经 PostgREST，**不需要连接池**） |
| 数据访问 | **Repository 适配器** —— 所有数据库访问必须经它，禁止在页面或 Route Handler 里直接发请求 |
| 身份 | **匿名会话方案 A** —— 服务端发 Token → SHA-256 落库 → HttpOnly Cookie |
| 部署 | Vercel，函数区域 **`hkg1`**（必须手动改，默认是美东） |
| AI | `AI_PROVIDER=disabled` 默认，只保留 `LLMProvider` 接口 |

## 四、开发步骤

> 每阶段的详细验收标准见《AI实施任务书》对应章节。
> **一次只做一个阶段，当前阶段验收通过才进入下一阶段。**

| # | 阶段 | 核心产出 | 执行方 |
|---|---|---|---|
| 1 | 项目骨架 | Next.js 项目、目录结构、`/api/health`、`hkg1` 区域配置 | agent |
| 2 | 数据库迁移设计 | 12 张表 + 6 个 RPC，**迁移 SQL 必须入库** | agent 写，**人工执行** |
| 3 | Repository + 线上探针 | Vercel → CloudBase 的 CRUD 全链路打通、耗时记录 | agent 写，**人工部署验收** |
| 4 | 匿名会话方案 A | Cookie 会话、Token 哈希、越权与伪造攻击测试 | agent |
| 5 | 内容数据管线 | `content/` 结构、校验脚本、导入脚本、来源字段 | agent + **人工核验资料** |
| 6 | 核心产品功能 | 测评 → 画像 → 学习路线 → 成长首页 → 资料检索 | agent |
| 7 | 受控任务编排器 | 工具注册表、白名单校验、`DisabledProvider` | agent |
| 8 | 安全加固 | Key 隔离、IDOR、CSRF、PostgREST 白名单、限流与幂等 | agent |
| 9 | 测试 | 单元 / 集成 / E2E，用户 A/B 数据隔离 | agent + **人工浏览器实测** |
| 10 | 部署 | Preview → Production → 回滚预案 | **人工确认** |

### 🛑 必须停下来等人工的节点

建远程仓库 · 建 Vercel Project · 填写环境变量与 Secret · 创建 CloudBase API Key · **在数据库执行迁移** · 核验并导入资料 · Preview 验收 · Production 发布 · 决定是否开源 · 最终提交。

> **Agent 不得绕过这些节点，也不得声称用户已完成未经验证的控制台操作。**

## 五、每个人怎么用自己的 agent

### 开工前，把这三样喂给你的 agent

1. **本文档** —— 统一所有人的步骤与边界
2. **你的阶段对应的《AI实施任务书》章节** —— 具体验收标准
3. **涉及到的基准文档** —— 产品看 PRD；碰数据库看《数据库交接说明》与《云开发实测记录》；写工程代码看《技术经验与开发规范建议》

### 给 agent 的规则（可直接复制）

```text
1. 先检查仓库现状，不要假设项目还没初始化。
2. 一次只实现一个可验收阶段，不要同时铺开多个功能。
3. 动手前先说明：目标、要改哪些文件、怎么验收。
4. 每阶段结束跑 Lint、Type Check、相关测试和 Build，报告结果后停止。
5. 所有数据库访问必须走 Repository，不要在页面或 Route Handler 里直接发 PostgREST 请求。
6. 私有数据的 userId 只能来自服务端会话，绝不接受前端传入的 userId。
7. Secret 不写进代码、日志或聊天记录；不要向我索要真实密钥。
8. 数据库迁移 SQL 必须进仓库，禁止只在控制台改表而不保存 SQL。
9. 实时 AI 默认关闭，不要为了演示效果擅自启用。
10. 平台行为与文档不符时，先写最小探针、记录结果，再改方案。
11. 遇到「必须人工完成」的步骤要停下来，告诉我该做什么、在哪个控制台操作。
```

### 全员禁止事项

- ❌ **更换技术栈** —— CloudBase 静态托管主体 / CloudBase 文档型数据库 / Supabase / Neon
- ❌ 默认启用第三方模型，或把 Agent SDK / CodeBuddy CLI 接入提交版主链路
- ❌ 多 Agent 系统、自动爬虫、知识图谱、论文 PDF 批量解析
- ❌ 导师主观评分或负面评价、论文代写、伪造引用或实验数据
- ❌ 提交 `.env.local`、真实密钥、API Key —— **本仓库是 Public，所有人可见**

### 提交方式

完整规则见 [CONTRIBUTING.md](../CONTRIBUTING.md)，简版：

| 改动类型 | 走哪条路 |
|---|---|
| **代码**、配置、依赖、SQL 迁移 | `dev/<你的名字>` → 测试通过 → PR → 队友确认 → 合并 |
| **文档小改**（只动 `*.md`） | 可直接提交 `main` |

**动手前一律先拉取。**
