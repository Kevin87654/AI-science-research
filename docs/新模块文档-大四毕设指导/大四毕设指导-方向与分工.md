# 大四毕设指导：方向与分工

> 版本：v0.7 ｜ 改动时间：2026-11-13 ｜ 用途：团队对齐方向与分工的内部文档，不提交给辅导员、不对学生发布。本文档仅供参考，对项目没有强制性约束，随开发随时改。
>
> **v0.7 的方向调整（2026-11-13 与学院开完会）**：**砍掉导师端**，产品只服务学生；
> 核心收窄为「**让学生知道选什么导师、做什么题目**」；时间轴保留但降级；重点放在「**有趣地摸清兴趣方向**」。

## 1. 这个项目是干什么的

把原来的「科研小助理」从"给大一新生做科研启蒙"，扩展出一个「大四毕设指导」入口（首页是身份入口，两个模块隔离），交付给学院辅导员老师，**不是毕设答辩项目**。

**第一性原理（这次会议定的四条）**：

1. **能早一点动手** —— 别等大四被流程追着跑，大三就该开始准备；
2. **动手之后有人可找** —— 给出方向，以及该联系哪个导师；
3. **以"了解老师"为基础** —— 不知道老师做什么，选导师就是撞运气；
4. **让学生知道整个流程** —— 往年什么时候选导师、什么时候写论文、每个阶段交什么。

**核心命题就一句**：让学生知道**选什么导师、做什么题目**。其余功能都为它服务，**不追求做全**。

**这一版原本做的是什么（为什么现在改）**：做成了"毕设进度管理 + 师生协作"——双时间轴、AI 提醒、周报审阅、会面邀约、站内消息、导师端。会议确认：**学院已经有一整套毕设流程系统**，导师不可能为这件事再学一个新工具。所以**导师端整体砍掉**，产品回到"学生怎么选导师、做什么题"。

**它要替掉的是这个困境**：现在学生靠**翻小红书经验帖、问学长学姐**搞清"选谁、做什么、什么时候"。我们要「**降低门槛，拉高注意度**」，把原本靠打听的事，变成学生愿意点开、看得下去的东西。

**辅导员的诉求（仍然保留）**：覆盖毕设流程信息（时间线、开题、答辩要求）。原定的两条时间线里，**学校官方线保留**（选题、开题、中期、答辩的节点、截止时间、材料要求），**个人/导师线随导师端一起下线**。

> 上一版写"导师搜索、兴趣匹配两条线保留但降级"——**这两条现在反而成了主线**，见 §4。

## 4. 要做什么（功能）

### 4.1 主链路（近两周先打通这一条）

```
学生身份进入 → 了解流程与往年时间（可跳过） → 有趣地摸清兴趣方向【重点】 → 匹配导师与课题 → 导师详情 + 联系方式（只展示）+ 建议
```

- **重点在第三环**：怎么**有趣地**把兴趣方向摸出来。后面的匹配、导师详情是被动承接。
- **流程与往年时间不是必须的**：学生可以跳过，但链路里要有这个入口（对应目的 4）。
- **没有兴趣方向怎么办**：不要求他有——直接**推荐最合适的**给他。
- **终点是"找到导师"**：落到导师详情页，**弹出联系方式**（只展示：邮箱 / 接访时间地点 / 主页），并给更多联系建议。

### 4.2 各环节要做到什么

| 环节 | 要做到什么 | 优先级 |
|---|---|---|
| 流程与往年时间 | 学生能看懂「往年什么时候选导师、什么时候开题、什么时候写论文、各阶段交什么材料」；现有学院 14 节点时间轴改造后作为这一环 | **降级，不优先** |
| 兴趣方向探测 | 用有趣的方式问出方向，收敛到 1–2 个可做的方向；没有方向时给推荐 | **最高** |
| 导师匹配 | 按方向 / 课题 / 招生表述匹配导师，能给出一份可对照的清单 | 高 |
| 导师详情 + 联系方式 | 展示研究方向、招生说明、接访时间地点、邮箱 / 主页——**只展示，不做站内消息** | 高 |
| 建议 | 联系导师的邮件 / 面谈建议、什么时候动手的时间建议 | 中 |

### 4.3 有趣化（自由探索，文档不约束）

怎么让这个东西"想用"，**暂时不在文档里定**：由邱欣怡、傅加贝自由探索——可视化、小游戏 / RPG 闯关、养宠物、
用所有老师的科研方向数据做"找地图 / 二分法"、城市路径等，都只是灵感。**产出与形式后续直接交流，文档不做约束、不设验收**。

## 5. 不做的事（红线）

沿用：不编引用、不猜名额、不代写论文、不评价导师人品 / 排名。
砍掉：导师"严厉 / 松弛"评价、匿名留言墙 / 评论。

**这次新增的"不做"**：

- **不做导师端**（导师登录、导师工作台、周报审阅、会面邀约全部删除）；
- **不做师生站内消息**（联系方式只展示，不做聊天）；
- **不做全面**：本轮只做"选导师 + 选题目"这一条，其他功能不铺开。

合规红线暂时就是"不评价导师、不排名、不编名额"，不动。

## 10.5 知识库 RAG（P1，待认领）

> **定位**：这是"以了解老师为基础"那条目的的直接落地——从"只答 12 条 FAQ、10 位老师"，
> 变成能翻遍我们手上全部资料来答。它与 M3（导师匹配与详情）共用同一份导师资料。

**一句话**：现在的问答只能答预先写死的 12 条 FAQ、10 位老师；这个任务是把我们手上**所有资料**做成一个知识库，让学生怎么问都能答、答案有出处，还能结合他自己走到哪一步。

**能做成什么样**

1. **流程问题不用再问辅导员**：「开题报告要写哪几部分？」「中期检查要不要交表？」「答辩前要准备什么？」——直接依据学院手册和 2027 届工作安排回答，并指出出自哪份文件。
2. **找导师不用靠打听**：「做具身智能的有哪些老师？」「谁明确欢迎本科生？」「某位老师的接访时间？」——从 163 位导师的资料里答，带来源。
3. **结合自己的进度回答**：「我下周要交任务书，现在该准备什么？」「开题被退回了，下一步怎么办？」——答案会看学生自己记的节点和学院时间轴。（进度功能降级后，这一条随之靠后。）
4. **跨资料串起来**：「我这个方向，学院有没有相关的讲座、比赛、课程？」——把网站收录、讲座、比赛一起翻出来。
5. **以后能长出去**：辅导员 / 导师侧的常见问题也能用同一套知识库答，换个视角而已。

**达成什么效果**

- **覆盖面**：从 12 条 FAQ + 10 位教师，扩到全部现有资料；问题不用预先设计，问法自由。
- **可信**：每个回答都能指回原文（哪份文件、哪一节、哪位老师的哪句话），学生可以自己复核。
- **诚实**：资料里没有就明说「资料里没有」，不编。
- **个性化**：问「我该怎么办」时，答案是结合他自己情况的，不是通用建议。
- **好维护**：新增一份手册、一批老师，放进去就能被问到，不用重新设计问答规则。

**首批语料（都是现有的）**：163 位导师信息（方向、招生说明、联系方式）、毕业设计平台的四份操作手册与撰写规范、学院 2027 届工作安排（14 个节点）、网站收录、12 条 FAQ、10 位已核验教师。后续逐步补充——讲座、比赛、课程等等。

**检索上下文**：学生自己的毕设节点与进度也一起带上。同一个问题，大三和大四、进度快和进度慢的，答案可以不一样。

**先后**：先做「学生端问答」，导师 / 辅导员侧放到后面；资料先用手上这些，边用边补。

**这个任务的性质**：不是一次做完的交付物，是给开发一个方向——先研究上面这些场景到底能做到什么程度、效果能不能达到，做出 demo 再谈。

**可以研究的几个问题（只是建议，不是要求）**：资料多起来以后，回答还能不能指回原文；学生自己的情况怎么和资料一起用；一问一答会不会慢到没法用；资料以后谁来维护、加一份手册要不要改代码。
