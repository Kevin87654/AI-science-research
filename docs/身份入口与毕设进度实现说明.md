## 1. 三条入口

## 4. 接数据库时改哪几处

仓库里**已经有**数据访问适配层（`src/server/repositories/`），
但**只覆盖两张表**：`sessions`（匿名会话的令牌摘要）与 `task_progress`（学习路线任务进度）。
**没有**账号表、导师-学生关系表、毕设节点表 —— 这三样需要新增。

### 4.1 建议的表结构

```sql
-- 账号：学号/工号即 id；密码只存哈希
create table public.accounts (
  id            text primary key,                       -- 学号 / 工号
  role          text not null check (role in ('student', 'mentor')),
  name          text not null,
  affiliation   text not null default '',
  detail        text not null default '',
  password_hash text not null,
  created_at    timestamptz not null default now()
);

-- 导师-学生关系：主键里带 mentor_id，查询必须带归属
create table public.mentor_students (
  mentor_id  text not null references public.accounts (id) on delete cascade,
  student_id text not null references public.accounts (id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (mentor_id, student_id)
);

-- 学生自建节点
create table public.graduation_nodes (
  id         uuid primary key default gen_random_uuid(),
  student_id text not null references public.accounts (id) on delete cascade,
  node_date  date not null,
  title      text not null check (length(title) between 1 and 40),
  note       text check (note is null or length(note) <= 200),
  created_at timestamptz not null default now()
);
create index graduation_nodes_student_date_idx on public.graduation_nodes (student_id, node_date);

-- 学生 ↔ 导师消息（当前是服务端内存，落库时按这张表）
create table public.graduation_messages (
  id          uuid primary key default gen_random_uuid(),
  student_id  text not null references public.accounts (id) on delete cascade,
  mentor_id   text not null references public.accounts (id) on delete cascade,
  sender_role text not null check (sender_role in ('student', 'mentor')),
  kind        text not null default 'text' check (kind in ('text', 'summary')),
  body        text not null check (length(body) between 1 and 2000),
  created_at  timestamptz not null default now()
);
create index graduation_messages_thread_idx on public.graduation_messages (student_id, mentor_id, created_at);

-- 已有 sessions 表加一列，把匿名会话与账号绑起来
alter table public.sessions add column if not exists account_id text references public.accounts (id);
```

四张新表同样要 `enable row level security` 且**不建 policy**（理由见《数据库交接说明》§5：
API Key 带 `bypassrls`，RLS 挡不住我们，归属过滤必须写在 Repository 里）。

## 5. 已知边界

- 账号只有 2 个（1 学生 1 导师），导师搜索只能搜到 `20220001`；
- 学生节点、导师小组都是**单浏览器**数据，换个浏览器就看不到；
- 联系消息**存在服务端内存**：同一台服务器上的两个浏览器能互见，进程重启或换实例就丢；
- 登录态没有过期时间，也没有跨设备同步；
- 学院节点是常量，没有"每个学生完成到哪一步"的记录 —— 现在只展示节点本身；
- 进度提醒 / 成果汇总的 AI 建议仅供参考，节点日期以学院通知为准。

## 6. AI 与即时通信（2026-11-12）

### 6.1 AI 改为 DeepSeek 直连

旧的 `@tencent-ai/agent-sdk` 会 spawn 一个 CLI 子进程，依赖 `SERVER_CODEBUDDY_API_KEY` 与
`serverExternalPackages` 那套部署配置。比赛结束后这条路已不可用（见《大四选导师-方向与分工》§R1），
本轮全部换成 OpenAI 兼容的 DeepSeek 直连：

| 项 | 现在 |
|---|---|
| 适配器 | `src/server/ai/client.ts`：`POST {base}/chat/completions` |
| 配置 | `SERVER_AI_API_KEY` / `SERVER_AI_BASE_URL` / `SERVER_AI_MODEL` |
| 线上状态 | ✅ **2026-11-12 已配并验证**：Vercel 里 Type=`Secret`、Environment 只勾 `Production`，Redeploy 后 `/api/ping` = `ai:connected`；提醒/汇总/问答三路都实测走通（见《部署与线上验证记录》§4.5） |
| 模型 | 默认 `deepseek-flash`；汇总任务用 `reasoning_effort: low`，避免 reasoning 吃掉正文 |
| 失败码 | `not_configured / timeout / empty / busy / failed`（调用方判据不用改） |

**两个新接口**（都要求匿名会话）：

- `POST /api/graduation/reminder`：对照学院 2027 届时间轴，返回 `{ source, headline, items }`。
- `POST /api/graduation/summary`：返回 `{ source, title, body, nodeCount }`，学生端一键写进会话。

`source` 是 `"ai" | "rule"`：模型不可用 / 输出不合法 / 未配密钥时，服务端直接返回
`buildRuleReminder` / `buildRuleSummary` 的结果，页面照常显示，只把角标换成「基础提醒 / 基础汇总」。

### 6.2 学生 ↔ 导师联系

- 学生端左侧栏「联系导师」，导师端左侧栏「联系学生」，共用 `ContactPanel`。
- 消息走 `GET|POST /api/graduation/messages`，前端每 2 秒轮询；页面不可见时暂停。
- 演示期消息存在服务端进程内存（`message-store.ts`），同一台服务器上的两个浏览器能互见；
  进程重启清空，Vercel 多实例不共享。落库表结构见 §4.1 的 `graduation_messages`。
- 账号还是演示登录，`senderRole` 由客户端声明；接真实登录后必须改成从会话解析发送方。

### 本机依赖布局的一个坑（2026-11-10 记录）

这台机器上 Node 24.21 + pnpm 11.19 的默认 `isolated` 布局会生成 junction，
Node 的 `require` 解析不进去（`require("@swc/helpers/...")` 直接 MODULE_NOT_FOUND），
表现为 `pnpm dev` / `next build` 报 `Could not find the Next.js package`。

本次验证是把布局换成 hoisted 才跑起来的：

```bash
pnpm install --frozen-lockfile --ignore-scripts --node-linker=hoisted
```

⚠️ pnpm 会在每次跑脚本前按配置校正布局，所以**没有把 `node-linker` 写进配置时，
下一条 pnpm 命令可能又切回 isolated**；只是看页面的话，装好后直接
`node node_modules/next/dist/bin/next dev` 也能起。部署端（Vercel / Linux）用默认布局即可，
不受此影响。
