# 项目测试的五层法 —— 流程与踩坑经验

> **类别**：随开发演进（按《总控文档》§一）—— 可直接改，不必等评审。
> **相关**：《技术经验与开发规范建议》（工程方法论）、`CONTRIBUTING.md`（分支与提交规则）。
> **来源**：2026-09-21 对 B 模块（测评 → 画像 → 路线 → 进度 → 成长首页）与 AI 自适应测评的一次完整验收，
> 包含 5 个真实缺陷的发现过程与 3 次"我自己的测试写错了"的记录。
>
> **核心原则：从快到慢、从本地到线上分层；每层都能独立收工。** 时间紧就跑前两层。

## 一、五层速查

| 层 | 目标 | 耗时 | 判据 |
|---|---|---|---|
| **0** 环境对齐 | 别在错的状态上测 | 1 min | `git diff --stat origin/main HEAD` 为空；端口 3000/3100 空闲 |
| **1** 静态 + 单测 | 挡住低级错误，不碰网络 | 15 s | `lint`/`typecheck`/`test`/`build` **四项退出码全 0**；`# fail 0` |
| **2** 本地端到端 | 真库 + 真 AI + **降级** | 5 min | `database-layer.mjs` 26/26；`identity-isolation.mjs` 44/44；无密钥时接口 200 且走规则 |
| **3** 线上冒烟 + 验收 | 真实部署与真实环境变量 | 3 min | 5 个页面 200；线上 `44/44`；无会话调接口 401 |
| **4** 功能走查 | 逐页面的行为与视觉 | 15 min | 见下方"第四层清单"；自动化 19 项 + 视觉 6 项 |
| **5** 演示演练 | 掐表 + 兜底话术 | 10 min | 两条路径的实测耗时（见下） |

### 第 1 层命令（注意 `NODE_OPTIONS=""`）

```bash
cd AI-science-research
NODE_OPTIONS="" pnpm lint       # 期望：ESLint 无任何输出
NODE_OPTIONS="" pnpm typecheck  # 期望：Types generated successfully
NODE_OPTIONS="" pnpm test       # 期望：fail 0（项数随模块增加，以 fail 0 为准，别写死数字）
NODE_OPTIONS="" pnpm build      # 期望：10 条路由
```

> ⚠️ **必须逐项单独捕获退出码**（如 `cmd > 日志 2>&1; echo $?`），**不要**用 `| grep` / `| head` 过滤后再看退出码 ——
> 管道会把退出码替换成末端命令的，构建失败会被显示成成功。**本轮实测中就因此误判过一次"构建全绿"。**

### 第 2 层四条命令

```bash
NODE_OPTIONS="" pnpm exec next start -p 3100          # 会自动加载 .env.local
curl -s http://127.0.0.1:3100/api/ping                 # 期望 database + ai 均 connected
node --env-file=.env.local scripts/verify/database-layer.mjs
node --env-file=.env.local scripts/verify/identity-isolation.mjs http://127.0.0.1:3100
# 降级验证：故意不给 AI 密钥
SERVER_CODEBUDDY_API_KEY="" NODE_OPTIONS="" pnpm exec next start -p 3100
```

> 💡 `SERVER_CODEBUDDY_API_KEY=""` 能真正屏蔽 `.env.local` 里的值 —— **Next 不覆盖已存在的进程环境变量**，
> 所以空串有效。这是"无密钥路径"最省事的造法，不用改文件。

### 第 3 层（线上）

```bash
B=https://ai-science-research.vercel.app
curl -s $B/api/ping                     # ai: not_connected 说明 Vercel 没配密钥
for p in / /assessment /profile /roadmap /dashboard; do
  printf "%-12s %s\n" "$p" "$(curl -s -o /dev/null -w '%{http_code}' -m 15 $B$p)"; done
# 线上 44 项隔离验收（会写真实数据库，脚本自清理）
NODE_USE_ENV_PROXY=1 node --env-file=.env.local scripts/verify/identity-isolation.mjs $B
```

### 第 4 层清单（逐页面，每条都写清"期望看到什么"）

**`/assessment`**：进门只有说明 + 一个开始按钮（不是一屏题目）；第一题**秒出**；可多选；
「不太清楚」与"选了最低档"表现不同；「上一题」能改，且**改完后面的题会重新规划**；AI 介入时带一句衔接语；走完自动跳画像。

**`/profile`**：阶段名 + 状态总结 + 2～5 项优势 + 2～5 项待补能力；兴趣标签；**3 条优先行动**（各带一句理由）；
底部有生成依据与时间；用示例答案时**必须显示「演示数据」角标**。

**`/roadmap`**：每项任务有预计耗时 + 可勾选的完成标准；完成/进行中/跳过/撤销都能用；备注能存（**超 500 字被拒**）；
⭐ **刷新后进度还在**；断网操作时**明确报错 + 有「重试」**。

**`/dashboard`**：无画像时是引导空状态（**不是假数据**）；有进度时显示当前阶段 / 下一项任务 / 路线进度 / 最近完成。

**横切**：**跨用户隔离**（普通窗口 + 隐身窗口互不可见）；360px 手机宽度无横向溢出；直接输 URL 访问各页正常。

## 二、方法论教训：测试本身怎么写才可信

这五条比"测出什么"更重要 —— **测试写错会得出错误的结论，而且看起来很像真的。**

1. **退出码不能被管道掩盖。** `pnpm build | grep ...` 的退出码来自 `grep`。要么重定向到日志再单独查 `$?`，要么直接看输出。
2. **断言别写成"看起来能过"的样子。** 我写过 `assert(deepens.length <= 3 + 20)` —— 那个 `+20` 让断言形同虚设，等于没测。
   **为了让测试通过而放松断言，是最坏的一种"通过"。**
3. **报结论前，先分清"测试写错"还是"产品错了"。** 本轮我有 **3 次**把测试脚本的问题误判成产品问题：
   - 无头浏览器里点击无效 → 其实是**页面还没水合**（不是按钮坏了）
   - 回退只点了 1 步却断言"回到第 2 题" → 断言写错
   - 点击前没等 `busy` 结束（AI 介入时按钮是 disabled 的）→ 脚本时序错
4. **一次测一条路径，相近路径要能区分。** "读取失败"和"保存失败"都渲染成告警条 —— 若只判断"有没有告警条"，
   就会把旧的那个当成新的。**判据要落在文案或专属标识上**（最后用"文案是否含『没有保存成功』"来区分）。
5. **测试数据必须自清理，而且要二次复核。** 跑完直接查真库确认残留为 0，别只信脚本说"已清理"。

### 怎么做浏览器检查而不装任何东西

系统自带 **Edge**，用它的无头模式 + 调试协议（CDP）即可，**零依赖、不下载 Chromium**（省掉约 500 MB）：

```bash
# 单张截图
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" \
  --headless=new --disable-gpu --hide-scrollbars --window-size=360,900 \
  --virtual-time-budget=8000 --screenshot="绝对路径.png" <url>
```

> ⚠️ **`--window-size` 设的是「窗口」大小，不是「视口」大小。** headless 下视口仍是默认宽度，
> 于是截出来的是**宽布局被裁到 360**——长句被右侧切掉，看起来完全像横向溢出。
> 本轮就因此报了一次假警：截图里文字明显被切，用 CDP 一量 `scrollWidth === innerWidth`，
> **页面根本没溢出**，是工具骗人。
>
> 要验证手机宽度**必须**用下面的 CDP 路径（`Emulation.setDeviceMetricsOverride` 改视口 +
> `Page.captureScreenshot` 截图），或者干脆只用 `--window-size` 看整体印象、**不要据它下"溢出"的结论**。

要交互时：用 `--headless=new --remote-debugging-port=9222 --user-data-dir=<临时目录>` 启动，
再用 **Node 内置的全局 `WebSocket`**（Node 22+）连 CDP：

| 目的 | CDP 调用 |
|---|---|
| 手机宽度 | `Emulation.setDeviceMetricsOverride({width:360,height:900,deviceScaleFactor:2,mobile:true})` |
| 点元素 | `Runtime.evaluate` 里找 button 后 `.click()` |
| 量横向溢出 | `document.documentElement.scrollWidth > window.innerWidth` + 找越界元素 |
| 模拟断网 | `Network.emulateNetworkConditions({offline:true,...})` |
| 截图 | `Page.captureScreenshot` → base64 落盘 |

> ⚠️ **每次导航后固定等 2.5～3 秒再交互。** 服务端渲染的 HTML 让 `h1` 立刻可见，但 React 还没接管，
> 此时 `.click()` 完全没反应 —— **既不改状态、也不报错**，极容易被误判成产品 bug。这个坑本轮踩了两次。

## 三、环境坑速查（现象 → 原因 → 处理）

| 现象 | 原因 | 处理 |
|---|---|---|
| `pnpm build` 报 `ERR_WORKER_INVALID_EXEC_ARGV` | 沙箱给 shell 全局设了 `NODE_OPTIONS=--use-system-ca`；Next 构建要 spawn Worker，Worker 不接受该参数 | **`NODE_OPTIONS="" pnpm build`** |
| `pnpm typecheck`/`build` 报 `EPERM: ...routes.d.ts` | `next start` 运行中会**锁住 `.next`** | 先停服务 |
| **构建路由表全打出来了、退出码却是 1** | `.next/trace` / `.next/trace-build` 不可写，收尾时报 EPERM | **删掉这两个文件再构建**，别当成代码问题 |
| Node 脚本访问 `*.vercel.app` 报 `UND_ERR_CONNECT_TIMEOUT`，而同一时刻 `curl` 能通 | 本机有系统代理；**curl 自己读代理，Node 的 fetch 默认不读** | **加 `NODE_USE_ENV_PROXY=1`**（不加会 0 项通过，极易误判成"线上挂了"） |
| 手机打不开本地服务 | `pnpm dev`/`pnpm start` **写死 `--hostname 127.0.0.1`**，只监听回环 | **`pnpm exec next dev --hostname 0.0.0.0 -p 3000`** |
| 手机能开页面但操作无反应 / 进度存不上 | 生产模式下 session Cookie 带 **`Secure`**（`shouldUseSecureCookie()` = `NODE_ENV === "production"`），手机用 `http://` 时浏览器不保存它 | 手机验证用 **`next dev`**（development → 不带 Secure） |
| `rm` 删不掉东西（Git Bash） | 沙箱 safe-delete 垫片要求绝对路径、且 `rm -rf` 目录会被拒 | 用**绝对 Windows 路径**逐个删文件；目录用 PowerShell `Remove-Item` |
| `git commit` 报 `could not open '.git/COMMIT_EDITMSG': Permission denied` | 该文件被"刚用过它的另一次提交"瞬时占用 | **重试一次**即可 |
| 改动已暂存但 `git commit` 返回 128 | 提交信息文件路径写错/被删；或上面的占用问题 | **不要重定向输出**，让 `fatal:` 露出来 |

## 四、本轮测试真正抓到的缺陷

| 缺陷 | 影响 | 怎么发现的 | 状态 |
|---|---|---|---|
| 用「示例答案」生成的画像**没打上演示标记**（`isDemo` 为 false） | 违反契约"演示数据必须显式标记"；演示结果与真人无从区分 | 第 4 层视觉检查 | ✅ 已修 |
| **第一题也要等 20～45 秒** | 用户在最不能等的一屏干等；且模型此时没有任何作答可参考，纯浪费 | 使用反馈 → 定位到"无作答时也调 AI" | ✅ 已修（第一题瞬时） |
| `abort()` 不保证中断 → 请求无限挂住 → **整站卡死** | 连 `/api/ping` 都超时 | 端到端联调时撞到 | ✅ 已修（`Promise.race` 硬截止 + 并发上限） |
| 任务进度**保存失败没有重试入口** | 与 PRD §19.3"失败可重试"不一致 | 第 4 层（断网模拟） | ✅ 已修 |
| AI 调用**间歇性返回空内容**（约三次里一次）→ 静默退回规则 | 用户白等一次调用，但流程不中断 | 反复联调 | ⚠️ 已降级 + 已加诊断，**根因未修** |
| 规则问答不认识否定意图 / Provider 返回数组会被污染 | — | 队友复测 | ✅ 已修（2026-09-22，C 模块迁入时一并修复） |

**共同点：前 4 个都不是"崩溃"，而是"看起来正常但不对"** —— 演示数据没标记、多等几十秒、静默降级、少了重试按钮。
这类缺陷不会报错，只能靠**主动走查**发现，所以第 4 层不能省。

## 五、AI 相关测试的特殊性

1. **单次调用 13～45 秒**（约 13～15 秒是 CLI 子进程固定启动开销，与提问长短无关）。
   → **任何"每题都调模型"的设计都要先算演示预算。** 当前用 `SERVER_AI_STEP_MODE` 控制介入频率，默认 `checkpoints`（每答完 3 题一次）。
2. **降级必须安全且可测。** 无密钥 / 超时 / 返回非法题号都要能让流程走完。
   实测无密钥时：接口 **200**、`decidedBy=rule`、**461 ms** —— 对比有密钥时的 20 秒级。
3. **造"无密钥环境"用 `SERVER_CODEBUDDY_API_KEY=""`**，不必改 `.env.local`。
4. **别忘了看 `/api/ping`。** 环境变量名字写错**不报错**，会静默退回内存实现 / 规则出题；
   `ai: not_connected` 是唯一露馅处。**部署后第一件事就是看它。**
5. **实测基线（2026-09-21）**：AI 单次决策线上 18～26 秒；完整测评 9 题 / 2 次 AI 介入 / 全程约 130 秒；
   「示例答案」快速通道到画像页 0.2 秒量级。**（参考值，不是验收门槛 —— 见《总控文档》§二。）**

## 六、给下一次的三句话

1. **先跑第 1 层**（15 秒挡住低级错误），再做别的。
2. **第 2 层的"无密钥降级"和第 4 层的"刷新后进度还在"千万别省** —— 分别对应"AI 挂了会不会全线崩"与"唯一落库的数据到底存住没有"。
3. **发现自己写错了测试，比发现产品有 bug 更值得停下来记一笔** —— 前者会让你把后者的结论也说反。
