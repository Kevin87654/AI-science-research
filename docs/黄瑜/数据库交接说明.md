### 2.2 方式二：HTTP / PostgREST（任何语言、任何工具都能用）

不依赖任何客户端，**这是最通用的接入方式**，也是团队选定的数据访问路径。
**环境变量名统一带 `SERVER_` 前缀**（工程代码只认带前缀的名字，理由见下方警告）：

```bash
# 环境变量（值由 Kevin 私发，填进本地 .env.local 与 Vercel Dashboard）
# SERVER_CLOUDBASE_PG_REST_BASE_URL = https://kevin-cloud-server-d8c078fa24b09.api.tcloudbasegateway.com
# SERVER_CLOUDBASE_PG_API_KEY       = <由 Kevin 私发，勿写入任何仓库文件>

# 读
curl -s -H "Authorization: Bearer $SERVER_CLOUDBASE_PG_API_KEY" \
  "$SERVER_CLOUDBASE_PG_REST_BASE_URL/v1/rdb/rest/<表名>?select=*&limit=5"

# 写（PostgREST 惯用法）
curl -s -X POST -H "Authorization: Bearer $SERVER_CLOUDBASE_PG_API_KEY" \
  -H "content-type: application/json" -H "Prefer: return=representation" \
  -d '[{"字段":"值"}]' \
  "$SERVER_CLOUDBASE_PG_REST_BASE_URL/v1/rdb/rest/<表名>"

# 调 RPC（路径固定为 /rpc/<函数名>）
curl -s -X POST -H "Authorization: Bearer $SERVER_CLOUDBASE_PG_API_KEY" \
  -H "content-type: application/json" -d '{"参数":"值"}' \
  "$SERVER_CLOUDBASE_PG_REST_BASE_URL/v1/rdb/rest/rpc/<函数名>"
```

> ⚠️ **2026-09-22 更正：漏掉 `SERVER_` 前缀会静默出错。** 本节原先给的是不带前缀的

## 4. schema 变更怎么做（重要）

**建表 / 改表必须走 migration，不要用裸 SQL。** 另外要特别注意：
**迁移不能由 Vercel 运行时执行**，必须人工在控制台 / CLI / 连接器里跑。

### 4.1 ⚠️ 两套文件命名约定，先对齐再动手

| | 人写源文件的约定 | 连接器 `applyMigration` 的约定 |
|---|---|---|
| 目录 | `scripts/migrations/` | `cloudbase/migrations/` |
| 文件名 | `001_extensions.sql`、`002_core_tables.sql` … | `<14位时间戳>_<name>.sql`，如 `20260920103000_init_core_tables.sql` |
| 名称约束 | 无 | 小写字母开头，**只能含小写字母和下划线，不能有数字** |
| 版本号 | 序号 | **14 位时间戳** `YYYYMMDDHHMMSS`，自己给，不要自动生成 |

**这两套不是二选一，而是"内容"与"投递"的关系** —— 建议：

- **人写的源文件放在 `scripts/migrations/`**（序号清晰、便于按阶段阅读和 review）；
- **实际执行时走连接器 `applyMigration`**，它会把一份 `版本号_名称` 的同内容 SQL 写到**本地文件**，
  并把它写进远端 `cloudbase_migrations.schema_migrations` 历史。
- **两个目录都要提交进仓库**，`cloudbase/migrations/` 是"线上到底跑过哪些迁移"的唯一权威记录。

> ⚠️ **实测提醒（2026-09-20）**：`applyMigration` 返回的 `localFileHint` 写的是仓库路径，
> 但**实测它不会写进仓库** —— 文件落在 **AI 助手的 MCP 运行目录**（`~/.learnbuddy/logs/mcp-runtime/` 下，不在项目内）。
> → 投递成功之后，**必须手动把这份 SQL 复制进 `cloudbase/migrations/`**，否则仓库里会缺这条记录。

> ⚠️ 不要绕开 `applyMigration` 直接用 `execute` 跑 DDL（默认会被拒绝）。绕过去的话，远端迁移历史会和仓库文件脱节，
> 后面想用 `fetchMigration` 对齐就对不上了。

### 4.2 其他要点

- `applyMigration` **不是增量**：每次要传**完整** SQL
- 可选传入回滚 SQL（`rollbackSql`）
- 执行前先 `planMigration` 预览，确认无误再 `apply` 并带 `confirm=true`
- 失败时先 `listMigrations` 确认版本有没有落库，**不要立刻用同一个版本号重推**

```
scripts/migrations/          # 人写源文件（序号编号体系）
├── 001_extensions.sql
├── 002_core_tables.sql
└── ...

cloudbase/migrations/        # 连接器实际投递的记录（14 位时间戳）
└── 20260920103000_init_core_tables.sql
```

> ⚠️ `cloudbase/migrations/` **不要指望工具自动创建** —— 见 §4.1 的实测提醒，投递成功后需**手动**把 SQL 搬进来。

## 5. 权限模型：PG 表走 RLS

- PG 表的权限控制是 **Row-Level Security**：
  ```sql
  ALTER TABLE public.xxx ENABLE ROW LEVEL SECURITY;
  CREATE POLICY "..." ON public.xxx FOR SELECT USING (...);
  ```
- ⚠️ **`managePermissions(resourceType="noSqlDatabase")` 对 PG 表完全无效** —— 那套规则只管 NoSQL 集合。
- 可用角色：`cloudbase_postgres`（默认）、`anon`、`authenticated`、`service_role`
- **API Key 的权限等级**：解码 JWT 可见 `role: service_role` + `is_system_admin: true` `【已实测】`
  → **这是管理员级权限**，等于环境的完全控制权。因此：
  1. **绝不能出现在前端代码、浏览器请求、公开仓库里**
  2. 前后端分离时，API Key 只放服务端环境变量（本项目约定用 `SERVER_` 前缀）
  3. 浏览器端要访问数据，走匿名/登录态 + RLS 策略，而不是把 Key 发下去

### 5.1 ⚠️ 三条必须知道的实测事实（2026-09-20 探针）

1. **这个 API Key 带 `bypassrls = true`，RLS 对它完全不起作用** `【已实测】`
   同一张开了 RLS 的表：我们的 Key 读到全部行、能写任意归属；`anon` 角色读到 0 行。
   → **RLS 机制本身有效，但保护不了我们自己** —— "用户之间互相看不见"**只能靠 Repository 层每次都带归属过滤**，
   并用"伪造他人标识"的用例守住。**持有管理员级 Key 不能替代用户鉴权。**
2. **没开 RLS 的表对低权限身份是敞开的** `【已实测】`：新表忘了开 RLS 时，`anon` 角色读到了全表。
   → **每张业务表都要显式 `enable row level security`**，哪怕我们自己走的是管理员 Key。
3. **单条 SQL 硬上限 8 秒** `【已实测】`：`statement_timeout` / `lock_timeout` 都是 8s，
   **函数内 `set_config` 覆盖无效**（属网关层限制）。→ 数据访问的超时预算按 **8 秒**设计。

> 另两条与写法有关：**RPC 里不要读 `request.headers`**（它包含调用方的 API Key）；**错误正文是数据库原文、会泄漏表名列名**，对外必须改写。
> 详见《数据库接入探针记录》§2、§5、§6。

## 6. 存储：PG 模式和你想的不一样 `【已核实】`

平台明确提示：PG 模式下浏览器上传必须用 **pgstore**：

```js
app.storage.from().upload('<bucket>/<key>', file)   // bucket 需先显式创建
```

- ⚠️ **`EnvInfo.Storages[]` 里列出的桶是 legacy NoSQL 桶，不是有效的 pgstore 目标。**
  直接拿它做浏览器上传会得到 `STORAGE_BUCKET_NOT_FOUND`，或请求打到 `PUT https://undefined/`。
- ⚠️ 本环境**没有可用的 NoSQL 实例**，因此**不要假设 `app.database()` 能用**。
- 云存储存在 ≠ 数据库是文档型。这两件事是分开的。

| 4 | `createFunction` 报 `additionalProperties` | 管控面接口不接受 `memorySize` 字段（免费版内存本就固定 256MB） |
| 5 | `createFunction type:"HTTP"` 报 `ResourceNotFound.BootstrapFile` | HTTP 型云函数**必须自带 `scf_bootstrap`**（自起 HTTP 服务监听 9000）；传统形态用 `type:"Event"` |
| 6 | `createFunction` 报「不支持修改…(HOME)」 | **平台禁止覆盖 `HOME`** → 改为在函数代码里 `process.env.HOME='/tmp'` 并注入子进程 |
| 7 | `updateFunctionCode` 报 `FUNCTION_UPDATING` | 上一次更新还在跑；**等 10 秒且状态 Active 再重试，不要连打** |
| 8 | 静态托管默认域名访问异常 | 见 §1 的警告：默认域名仅测试用，正式要自定义域名 + ICP 备案 |
