## 2. 环境变量

前两个 **必需**，其余按需；**名字必须带 `SERVER_` 前缀**：

| 变量名 | 必需 | 说明 |
| --- | --- | --- |
| `SERVER_CLOUDBASE_PG_REST_BASE_URL` | ✅ | 网关地址 |
| `SERVER_CLOUDBASE_PG_API_KEY` | ✅ | 管理员级密钥，**建议开启 Vercel 的 "hide value after saving"** |
| `SERVER_CODEBUDDY_API_KEY` | ✅ **已配** | AI 的密钥。**2026-09-22 核实：已接入并生效** —— 测评出题与科研问答都走它，多个页面已出现「模型生成」角标 |
| `SERVER_AI_QA_MODE` | 按需 | **问答链路的 AI 开关**。只有**精确写 `off`** 才关，其他任何值（含空、拼错）都算开；不配这个变量也等于开。设 `off` 后问答秒回规则回答（内容仍是带来源的规则答案，只是不再出现"模型生成"角标） |
| `SERVER_AI_STEP_MODE` | 按需 | 测评出题的 AI 介入频率，线上用 `checkpoints`（每答完 3 题）。**环境变量优先于代码默认值** |
| `SERVER_AI_TIMEOUT_MS` | 按需 | 单次模型调用超时，默认 60000。⚠️ 问答链路另有一个 **120 秒下限**，填得比它小不会被采纳 |

- Environment 至少勾 **Production + Preview**。
- 🚨 **变量名写错不会报错。** 应用找不到数据库那两个变量会**静默退回内存实现**——页面照常打开，但数据每个请求一份、重启即清空。唯一露馅的地方是 `/api/ping` 会显示 `"database": "not_connected"`。**部署完必须用 §4 的第 1 步验证一次。**
- ⚠️ Vercel 的配置页会显示 "Environment Variables **N Detected**"——那是从仓库的 `.env.example` 读到的**变量名，值为空**。**不要直接点 Deploy**，必须展开把真值填进去。
- ⚠️ 粘贴值时留意别带多余的空格或换行（API Key 是 932 字符的长串，从别处复制容易多带换行）。
- ⚠️ **改完环境变量要重新部署一次才生效**（Vercel 会提示 Redeploy；实测有时不重新部署也会生效，但别依赖这个）。

## 5. 中国大陆可达性【已实测】

### 5.0 结论

**`*.vercel.app` 默认域名在中国大陆打不开；但 Vercel 本身在大陆是可达的**（§5.2 有对照实验），换成自定义域名即可解决。

**本轮已决定不买域名**，依据与备选做法见 §5.3。

### 5.1 默认域名确实不可用

| 测试 | 结果 |
| --- | --- |
| 系统 DNS 解析 `ai-science-research.vercel.app` | 返回 `128.242.240.20` —— **不在 Vercel 的 IP 段内**（Vercel 用 `76.76.21.0/24` 与 `66.33.60.0/24`）→ 典型的 **DNS 污染** |
| 对该地址发起 TLS 连接 | 握手阶段被重置（`Recv failure: Connection was reset`） |
| 人工指定干净 IP、但仍用 `*.vercel.app` 作 SNI | 同样被重置 → **不只是 DNS 污染，这个域名本身也被针对** |
| 另一例 `swr.vercel.app` 解析 | `199.59.149.235`（同样是污染 IP），连接超时 |
| **中国电信校园网 / 中国电信移动数据** | **打不开**，浏览器提示"响应时间太长"【Kevin 真机实测】 |
| 挂境外节点（美国） | 可以打开【Kevin 真机实测】 |

⚠️ **注意区分两个域名**：被针对的是**部署出来的网站域名**（`*.vercel.app`）；**控制台域名 `vercel.com` 没有被污染**，大陆直连 200、仅 0.20 秒。两者经常被混为一谈。

### 5.2 对照实验：Vercel 的服务器在大陆并没有被封

用**已知由 Vercel 托管、但绑定了自定义域名**的站点做对照，全程**直连、不走代理**：

| 站点 | 解析到的 IP | 结果 |
| --- | --- | --- |
| `react.dev` | `76.76.21.61` ← **Vercel 原生 IP 段** | **200，1.45 秒** |
| `tRPC.io` | `76.76.21.21` ← **Vercel 原生 IP 段** | **200，1.92 秒** |
| `astro.build` | `104.18.0.156`（Cloudflare 前置） | 200，0.65 秒 |
| `zod.dev` | `172.67.180.179`（Cloudflare 前置） | 200，1.72 秒 |
| `vitest.dev` | `52.74.6.109` | 200，1.15 秒 |
| **`swr.vercel.app`**（默认域名） | `199.59.149.235`（污染 IP） | **超时失败** |

→ **同一家平台、同一批 IP 段：自定义域名能开，默认域名打不开。被针对的是 `*.vercel.app` 这个域名，不是 Vercel 的服务器。**

### 5.3 决策：本轮不购买自定义域名

**2026-09-20 决定，本轮不买。** 依据：

1. **赛事侧主动推荐了 Vercel。** 《赛事群答疑》里老师的原话是"有链接就可以了，**可以用 Vercel**，其他的也可以"——这是主办方给出的建议，说明评审路径不依赖"评委在中国大陆网络下直连打开该链接"。
2. **链接本身不是初赛硬门槛。** 同一位老师明确说过"**初赛提交 demo 即可，不用部署到正式环境**"，且"在 LearnBuddy 上搭建的智能体可以有多种形式"。
3. **成本与收益不成比例。** 自定义域名需要额外花钱与配置；而带宽/线路仍由境外节点决定，Vercel 官方也不保证大陆稳定性——买域名只是"更可能通"，不是"一定通"。

#### 零成本的三条并行措施

即使不买域名，也建议在提交材料里补齐这三点，避免"评委打不开就白扣分"：

1. **在作品说明里如实标注**：链接为 Vercel 部署，中国大陆网络环境下可能需要代理访问；若无法打开，可参考 Demo 视频。
2. **让 Demo 视频完整覆盖可演示的内容**——视频不受网络条件限制，是初赛最稳的呈现载体。
3. **保留源码可运行性**（仓库根目录有 `run-dev.bat`），评审若需要可本地起服务。

#### 如果后续需要大陆稳定访问（例如进入决赛、或链接变成硬门槛）

改动只有一处，不需要换平台：

- **不需要备案** —— 备案只针对"使用中国大陆境内服务器"的场景；域名解析到境外主机不需要备案。
- 后缀选便宜的即可（`.top` / `.xyz` / `.icu` 一类，约 ¥10–30/年）。
- DNS 解析：CNAME 指向 **`cname-china.vercel-dns.com`**（Vercel 面向中国大陆的专用入口，比默认的 `cname.vercel-dns.com` 多一个 `china`）。
  ⚠️ 如果 Vercel 的域名卡片报 `Invalid Configuration`，**先用它提示的默认 CNAME 值完成校验，看到验证通过后再改成 china 版**。
- 若 DNS 托管在 Cloudflare：**验证阶段用灰云（DNS only）**，看到两个绿勾之后再决定要不要开代理。
- 配好后需要**重跑 §4 的两项验证**，并**重新做一次手机真机实测**。

### 5.4 换平台并不是更好的选择

在没有自己域名的情况下，**境外平台普遍**存在同样的大陆可达性问题，换一家未必更好。已核实的两例：

- **腾讯云 EdgeOne Makers**：免费版额度很大、支持 Next.js SSR，但官方文档写明其**默认域名在中国大陆网络下只能用"系统生成的预览链接"访问、有效期 3 小时**；想稳定访问必须绑定**已备案**的域名。
- **CloudBase 默认域名**：大陆可访问，但官方定位是"仅适用于开发测试阶段"，且 2025-10-09 之后创建的环境会**长期带一个访问提示中间页**；官方建议生产环境绑定已备案的自定义域名。

→ 结论：**"有没有域名"才是决定大陆能否访问的变量，不是"用哪个平台"。**

### 5.5 赛事侧的口径（降低这一项的紧迫性）

《赛事群答疑》里老师原话：**"有链接就可以了，可以用 Vercel，其他的也可以"**，且 **"初赛提交 demo 即可，不用部署到正式环境"**。→ 链接不是初赛的硬门槛，但既然只需一个域名就能解决，建议还是把它配好。

## 7. 复现方式

全部是标准 HTTP 调用与仓库内脚本，不依赖任何专有 SDK。

```bash
# 线上自检（不需要密钥）
curl -s https://ai-science-research.vercel.app/api/ping

# 线上隔离验收（需要本地 .env.local，仅用于跑完后的清理）
node --env-file=.env.local scripts/verify/identity-isolation.mjs https://ai-science-research.vercel.app
```

本地对照：

```bash
node_modules/.bin/next build && node_modules/.bin/next start -p 3100
node --env-file=.env.local scripts/verify/identity-isolation.mjs http://127.0.0.1:3100
```

> 💡 **在需要走代理的机器上跑上面的 Node 脚本时，要加 `NODE_USE_ENV_PROXY=1`。**
> Node 的 `fetch` 默认**不读** `HTTP_PROXY`（只有 curl 读），否则会报 `UND_ERR_CONNECT_TIMEOUT`，很容易误判成"部署失败"。
