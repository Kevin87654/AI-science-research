# 数据访问

接口在 `types.ts`，当前生效的实现是 `in-memory.ts`，实例在 `index.ts` 里导出。

**接入真实数据库时只改 `index.ts` 一处** —— 换成 PostgREST 实现即可，接口与调用方都不用动。这正是「外部依赖走适配器层」这条要求的落点。

## 三条约束

1. **所有用户数据方法的第一个参数必须是 `userId`。**
   我们的 API Key 带 `bypassrls`，数据库的行级权限对我们完全无效（见《数据库接入探针记录》§6），
   所以接口层面就不给"不带归属的查询"留入口。实现里也不允许"查全表再过滤"。

2. **有上限的等待。** 单条 SQL 在网关侧硬上限 **8 秒**，真实实现必须带超时，并把超时映射成 `TIMEOUT`，
   不要把网关的原始错误抛给调用方。

3. **内存实现不是持久化。** 进程重启即丢，Serverless 上每个实例各有一份。
   现在用它只是为了让第一条流程先跑通、并被测试覆盖。

## 关于 `.ts` 扩展名

`in-memory.ts` / `errors.ts` 以及 `*.test.ts` 之间的运行时导入带显式 `.ts` 扩展名。

原因是单测用 **Node 自带的测试运行器**（`pnpm test`）直接跑 TypeScript 源码，**不引入任何测试框架**；
Node 的类型擦除不做路径解析，相对导入必须写全扩展名。
`tsconfig.json` 里的 `allowImportingTsExtensions` 就是为此打开的。

其余目录（`app/`、`components/`、`services/`）保持不带扩展名的写法，与 Next.js 的解析方式一致。
新增**会被单测直接加载**的模块时，请沿用这个约定，并保持该模块不依赖 `@/` 别名。
